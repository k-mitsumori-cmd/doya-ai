# 料金画面へサーバー確認済みセッションを渡す

本人の料金画面で、名前と据え置き契約は表示される一方、会社メンバー欄だけがログインを求める状態を確認しました。同じブラウザのセッションAPIには本人IDがあり、料金画面を新しく読み込むとメンバー欄は復旧しました。

料金ページはgetServerSessionで本人を確認していましたが、そのセッションをShellGateへ渡していませんでした。ShellGateは渡されたセッションでNextAuthのProviderを初期化するため、未指定の場合は外側に残るクライアント状態へ依存します。料金ページから確認済みセッションを渡し、本人ID（なければメール）をReactのkeyにします。本人が変わったら古い画面を終了し、同じ本人の再描画では入力を保持します。

回帰試験は、実際のasync PricingPage・ShellGate・PricingV2・TeamManageと、実際のNextAuth SessionProvider/useSessionをReact/jsdomで実行する26条件です。古い未認証・別本人のcontext、本人切替、遅いメンバーと請求応答、同じ本人の入力保持、ログアウト、匿名、セッション取得失敗、本人ID欠落、APIの権限拒否を通常とStrictModeで確認します。

旧ソースは6成功/20失敗でした。セッションを渡すだけの対照は21成功/5失敗で、本人切替や遅い応答の条件が残りました。本人をkeyにした修正版は26成功、React/NextAuthの警告とエラー通知は0でした。初期の試験環境でAPI応答を誤って扱った結果は、これらの最終対照には含めません。

サーバー認証・会社・旗・HTTPは合成境界です。共通枠の装飾と無効な機能の子要素は代替しています。Reactの同一rootへ新しいサーバーpropsを渡す条件であり、実際のNext.js遷移や別アカウントによる本番操作は未確認です。権限は既存のAPIが判定し、この修正で料金・価格・購入席数や認証情報を変更しません。試験の通信は合成GETだけで、実際の購入・招待・通知は実行しません。

# HRの旧表示ヘルパーと強制上限の一致

共通料金モジュールのgetHrEmployeeLimitByUserPlanとgetHrAiLimitByUserPlanを、実際のHRのプラン判定と上限に合わせます。現srcのシンボル検索では定義以外の直接参照は見つかっていません。現在の画面で誤表示や誤請求が発生したことを示す修正ではありません。

従来はSTARTERなどの有料別名、前後の空白、ENTERPRISEの従業員上限で正本と値が異なりました。実際のhrPlanTierを使い、ENTERPRISEの従業員上限はgetOrgPlanLimitsと同じ-1を返します。DOYA_DISABLE_LIMITS=1の既存の動作は維持します。HRの強制上限やStripeの商品・価格・購入席数は変更しません。

回帰試験は19種類の入力と既存の上限無効化設定2条件です。実際のHR判定と強制上限を読み込み、独立した固定の期待値でも確認します。共通の検査ローダーでは、この料金ファイルからの純粋なHR判定の読込だけを追加します。独自の勤怠SQL検査では読込許可に同じ実モジュールを追加し、従来の権限・人数制限の検査を維持します。

登録済みの全体回帰で実行し、CIは21条件の結果と5ソースのハッシュを保存します。これは純関数と合成環境変数の検査で、実際の画面、購入、請求、顧客データの検証ではありません。

# SEO記事画面の非同期処理の範囲

記事IDが切り替わったあとに、旧記事の読込結果や画像生成の権限確認が返っても、新しい記事の状態や自動処理へ反映しない。読込要求は記事IDごとに保持し、画面終了またはID変更で中断する。取得した記事IDが要求と一致しない場合も反映しない。

画像生成の自動試行は、現在のID・取得した記事ID・権限確認の有効性が一致する場合に限る。auto=0、未ログイン、権限不足では自動生成しない。通常の自動生成と手動生成は維持する。既に送出した生成要求の取り消しはこの変更の対象外。

## 回帰テスト

`node scripts/security-regression/verify-seo-article-auto-scope-mounted.cjs` は記事ページ本体と関連6モジュールをReact/JSDOMにマウントする。遅延応答、ID切替、StrictMode、画面終了、auto=0、未ログイン、権限不足、応答ID不一致、次の記事の自動生成、手動生成の14群を確認する。通常の `npm run test:security` に含まれる。

ネットワークと時刻処理は合成し、表示用子コンポーネントをスタブに置き換える。実際のHTTP、AI、DB、通知は呼ばない。出力先は `DOYA_SEO_PAGE_EVIDENCE_DIR`、未指定なら一時ディレクトリ。レポートには使用ソースのハッシュと実ネットワーク要求数を保存し、CIでは7日間保持する。

この検証は同じページのインスタンスを保持してパラメーターを変更する条件を作る。実際のNext.js画面遷移でインスタンスが保持されることや、ネイティブブラウザでの表示は確認していない。SEOジョブ画面も別の検証対象として残る。

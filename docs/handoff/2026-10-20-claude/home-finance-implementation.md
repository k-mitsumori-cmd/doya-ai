# 経営ホームの収支正本連携（2026-10-20）

## 変更した内容

経営ホームへ収入管理・支出管理の読み取りを追加しました。DBモデル、公開区分、契約、支払い処理は変更していません。集計は組織や招待を作成・更新せずに行います。本番未反映です。

`src/lib/home/finance-read.ts` が、最新の既存所属を一度だけ選びます。所属がINACTIVEか未知の役割なら、過去の所属や別組織へ移らず `no_access` にします。既知のmember以上だけが対象です。集計後にも同じ所属を確認し、収入組織の支出設定3項目も照合します。支出は収入より早く読み終わる場合があるため、全集計の最後にも同じ支出所属を確認します。

支出の選択は既存の `resolveExpenseLink` に従います。明示されたexpenseのIDを、最新の支出所属へ置き換えません。promaneの設定と、旧データの「source未指定＋promane ID」も保持します。取り込み元の設定を書き換える処理はありません。リンクがなく支出管理を単独で読む場合は、選択した支出組織の出金を独立した欄に表示し、収入側の粗利には使いません。

`homeIncomeSummary` には、ホーム用に支出を読まない選択肢を追加しました。これにより、支出の障害で売上予定・請求済み・入金まで失われることを防ぎます。既存の収入APIは引数を変えておらず、従来どおり支出も読みます。支出adapterの所属確認には、ACTIVEに加えて既知の役割の確認を追加しました。

## 数字と表示

| 項目 | 基準 | 扱い |
|---|---|---|
| 売上予定 | 計上月・税抜 | 収入管理の予定と請求済みを含む合計 |
| うち請求済み | 計上月・税抜 | 売上予定の内訳。別途足さない |
| 入金額 | 受取日・税込 | 売上予定とは合算しない |
| 粗利 | 計上月・税抜の予定売上から費用を引く | 明示リンクしたexpenseが読み取れた場合だけ算定 |
| 出金 | 支払日・税込、源泉控除後の支払いと源泉税納付 | 粗利から引く費用には使わない |
| 計上費用 | expenseの計上月・税抜 | 額面を一度だけ計上し、源泉税の納付行を除く |

promaneは税区分が混在するため、厳密な税抜粗利へ使いません。設定は保持し、案件の参考情報として表示します。取得失敗・権限なし・未接続は未算定です。正常な未使用と確認できた場合だけ、営業管理・見積・プロマネの参考値を表示します。当月の金額が0でも、契約がある収入管理を未使用へ戻しません。

新旧Dashboardに共通の `FinanceOverview` を追加しました。収入管理を使っている場合、主カードを売上予定・請求済み・入金・粗利の4枚へ切り替えます。営業パイプラインと案件別収支は参考欄に残し、主カードへ合算しません。収入と支出は組織名と集計元をそれぞれ表示します。失敗時は「—」と理由を表示し、0円へ置き換えません。

請求漏れ・入金遅延は、既存readが返すactionから新UIの今日やること、旧UIの要対応、エージェントの回答へ渡します。エージェントの売上回答も同じ正本を使います。

集計開始時の時刻を一度だけ固定し、JSTの当月・今日・旧ツールの期間・予定の範囲・`generatedAt`へ渡します。

## 実行した確認

`scripts/security-regression/verify-home-finance.cjs` は、実read関数、ホーム集計、GETハンドラ、新旧Dashboard、エージェントを合成Prismaデータで実行します。実DB接続、認証の迂回、実顧客データ、有料プロバイダーは使いません。書き込み操作とネットワーク呼び出しは、実行されたら検知して失敗させます。

28ケースで、次を確認しています。

- 税抜売上100・税込入金110・税抜費用40から、粗利60になること。
- 源泉税納付を含む出金44を粗利へ使わず、計上月と支払月も分けること。
- 明示リンク先と最新支出所属が違っても、リンク先だけを読むこと。
- 複数の収入所属を合算せず、最新1組織を使うこと。
- 他ユーザー、未知の役割、INACTIVE、集計中の失効、支出設定の変更で金額を返さないこと。
- 全集計の最後に失効した支出所属も検知し、収入は残して粗利を未算定にすること。
- 正常な未使用と取得失敗を区別し、契約0件は代替可能、当月0円は収入管理を維持すること。
- 支出の障害でも収入を保持し、既存の収入APIの既定動作は変えないこと。
- promaneの設定を保持し、税抜粗利へ使わないこと。
- JSTの月・年の境界、請求漏れ・入金遅延、両UIとエージェントのnull/0表示。
- 実GETを通して書き込み0、プロバイダー呼び出し0であること。

# Slack 通知の決まり（全アプリ共通）

版: 1.2.0（2026-10-25）

スリスタのすべてのアプリ・ツール・自動実行から Slack に送る通知に、この決まりを使う。
ドヤAI 以外のリポジトリでも同じ形にするため、部品は1ファイルにまとめてある。
ドヤAI での使い方と通知の一覧は `docs/slack-notifications.md` を見る。

## 1. 形

どの通知も、次の順に並べる。

```
<!channel>                              ← 緊急のときだけ
*【重さ】アプリ名｜種類：件名*            ← 見出し（1行目）
発生時刻：2026/10/25 9:00:00（日本時間）
本文（何が起きたか、次に何をするか）
- 項目名: 値
リンク: <https://...|管理画面を開く>
```

- 見出しは必ず1行目に置く。Slack の通知の一行表示に出るのは1行目だけだから。
- Block Kit を使うときは、先頭の header ブロックに同じ見出しを入れる（`emoji: false`）。
- 発生時刻は日本時間で書き、「（日本時間）」を添える。
- 本文は「何が起きたか」を先に、「次に何をするか」を後に書く。
- リンクは最後にまとめる。表示名は「管理画面を開く」のように、開いた先が分かる言葉にする。

## 2. 重さ

| 重さ | 使う場面 | @channel |
|---|---|---|
| 緊急 | 人がすぐ動かないと損が出る（停止、支払いの失敗、課金の不整合、エラーの急増、クレジット切れ） | 付ける |
| 要対応 | 今日中に誰かが確認する（処理のエラー、お問い合わせ、日報の未着、解約） | 付けない |
| お知らせ | 読み流してよい（登録、利用、入金、定期レポート） | 付けない |

迷ったら軽い方を選ぶ。@channel が日常的に鳴ると、本当に急ぐ通知が埋もれるから。

## 3. 種類

| 種類 | 対象 |
|---|---|
| エラー | 処理の失敗、停止、応答の遅れ、端末からのエラー報告 |
| 売上・課金 | 申し込み、購入、入金、返金、解約、支払いの失敗、課金の点検 |
| 利用状況 | 登録、ログイン、利用、運用の確認 |
| お問い合わせ | ご意見、問い合わせ、受信メール、申し込みフォーム |
| 定期レポート | 日報、週報、月報、朝刊、配信やコストのレポート |

## 4. 文面

- 絵文字を使わない。`:tada:` のようなコードも、文字の絵文字も使わない。評価の ★ と矢印（→）は記号として使ってよい。
- 日本語の丁寧な形で書く。「確認してね」「〜だよ」「いくよ！」ではなく、「確認してください」「〜です」と書く。
- 「！」と太字を多用しない。太字は見出しと区切りの小見出しだけにする。
- 1文は30〜45文字を目安にし、主語と述語を対応させる（yomiyasu の原則）。
- 利用者が書いた文章（お問い合わせの本文など）は手を加えずに載せる。絵文字もそのまま残す。
- 個人情報（メールアドレス、氏名）は、対応に要る通知だけに載せる。一覧で並べない。
- Webhook の URL、トークン、パスワードを本文にもログにも出さない。
- エラーと課金の通知（kind が error と billing）では、部品が本文・ブロック・コードの中を必ず伏せる（1.2.0）。伏せるのは、メールアドレス、Bearer、JWT、Stripe などのキー、Slack の Webhook とトークン、token= や password= の値、URL のクエリ。照合用の ID（UUID）は残す。
- 利用者が書いた文字列を載せるときは、`escapeSlackText` か `excerpt`（冒頭80字）を通し、`<!channel>` やリンクの差し込みを防ぐ。メールアドレスは `maskEmail` で伏せる（1.1.0）。

## 5. 間引き

- 同じ送り先に同じ内容（時刻の数字だけ違うもの）を、5分以内に二度送らない。
- エラーは、同じ発生箇所について10分に1回までにする。急増の通知は別に1回だけ送る。
- 同じ人のログインのように繰り返す出来事は、人ごとに数時間に1回までにする。
- 定期レポートは、配信の記録（DB など）を残して1日1回にする。再実行で二重に送らない。
- メモリでの間引きは、サーバーレスの複数のインスタンスをまたぐと効かない。確実に1回にしたい通知は DB に記録する。

## 6. 部品

正本はドヤAI リポジトリ（k-mitsumori-cmd/doya-ai）の `src/lib/slack/notify.ts`。
外部のパッケージに依存せず、`fetch` と `AbortSignal` だけを使う。
Next.js、Cloudflare Workers、Node 18 以降のどれでも動く。

### 入れ方

1. `src/lib/slack/notify.ts` を、そのリポジトリの lib にそのままコピーする。中身は書き換えない。
2. 版（`SLACK_NOTIFY_VERSION`）を、そのリポジトリの README か AGENTS.md に書いておく。今の版は 1.2.0（呪い日記・ゆるせん・推しにマイル・ヒトリジメに入れてある）。
3. 既存の送信箇所で、`fetch(webhook, …)` を `postSlack` に置き換える。

TypeScript でない Node のスクリプト（`.mjs`）では、型の注釈だけを外した `.mjs` 版を置いてよい。

### 使い方

```ts
import { postSlack } from './lib/slack/notify'

await postSlack(process.env.SLACK_EVENT_WEBHOOK_URL!, {
  text: [
    '*アプリ内購入が完了しました*',
    `発生時刻：${new Date().toLocaleString('ja-JP', { timeZone: 'Asia/Tokyo' })}（日本時間）`,
    '- 商品: 呪いの追加枠',
  ].join('\n'),
}, {
  meta: { app: '呪い日記', kind: 'billing', severity: 'info' },
})
// → *【お知らせ】呪い日記｜売上・課金：アプリ内購入が完了しました*
```

- `postSlack` は、見出しをそろえ、絵文字を外し、間引いてから送る。Slack が200以外を返したら throw する。
- 間引きのキーと時間は `dedupeKey` と `dedupeWindowMs` で変えられる。`dedupeWindowMs: 0` で間引かない。
- 送信せずに整形だけしたいときは `styleSlackPayload(payload, meta)` を使う。
- テストでは `fetchImpl` にモックを渡す。実際の Slack には送らない。

## 7. 送り先

- 送り先の環境変数の名前は、各リポジトリの今の名前のままにする。名前を変えると、Vercel や Cloudflare の設定を変える必要が出るから。
- Slack の Incoming Webhook は、作ったときに選んだチャンネルに固定で送られる。送信が200なのに届かないときは、Webhook の投稿先チャンネルを疑う。

## 8. 変えるときの決まり

- 決まりを変えるときは、この文書と `src/lib/slack/notify.ts` の版を上げ、各リポジトリのコピーを同じ版にそろえる。
- Slack に入っている連携アプリ（GitHub・Vercel・HubSpot など）の通知の形は、この部品では変えられない。連携アプリの設定は Slack の管理画面で行い、変える前にユーザーの承認を得る。

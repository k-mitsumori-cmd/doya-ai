# ドヤくんの知らせ（ポップアップと案内）の設計

2026-10-25 作成。ブランチは `feat/notice-parts` です。見本は https://claude.ai/artifact/3n7KxcEPrxB1rVbB81sfjj にあります。

## 1. 目的

ツールの中で出す知らせを、1つの部品にそろえます。アプリのように、楽しく分かりやすく使えるようにします（ユーザーの依頼、2026-10-25）。

## 2. 共通の決まり

- 同時に出すのは1つだけです。順番は、エラー → 承認待ち → 新機能 → ヒントです。
- エラーは、表示中の承認待ち・新機能・ヒントより先に出します。表示中のものは列に戻します。
- 作業中（入力中・POST の通信中・ツールが `holdBusy()` した間）は出しません。エラーだけは作業中でも出します。
- once の知らせは、閉じたら二度と出しません。見た記録は、ユーザーごとに端末へ残します（DB には書きません）。
- 767px 以下は下からのシートで、下へ引くと閉じます。768px 以上は右下のカードです。
- ドヤくんの絵を添えます。ドヤくんの表示オフ（DoyaPowerFx の mascot）なら文字だけにします。
- 動きを減らす設定では動かしません。絵文字は使いません。
- 外部の広告（HubSpot の CTA）とは別物です。広告を隠す仕組みは `ServicePopupGuard` のままです。

ツールから使うときは、次のように書きます。

```tsx
const notice = useNotice()
notice.notify({ title: '保存しました', action: { label: '取り消す', onClick: undo } })
notice.push({ id: 'quote:first', kind: 'hint', once: true, pose: 'point', eyebrow: 'ヒント', title: '…' })
notice.tip(buttonEl, { id: 'quote:rate', title: '粗利率', body: '…', once: true })
const release = notice.holdBusy() // 長い生成の間。終わったら release()
```

旗が off のとき、`useNotice()` はどれも何もしません。ツールの側で旗を見る必要はありません。

## 5. 次の候補（他社の使いやすさの調べ、メインの提案リスト 9章）

画面に関わるものを、知らせの共通部品のあとの候補として並べます。順番の考え方は次の3つです。

- 今ある部品（知らせ・エージェント・シェル）の上に足せるものを先にします。
- 本物のエージェントを広げる前に、安全の決まりを入れます。
- DB の表を新しく作るものは、設計を先に出して、実装はあとにします。

| 順 | 項目 | 他社調べの順位 | 大きさ | 先に要るもの | 担当の案 |
|---|---|---|---|---|---|
| 1 | エージェントの1回あたりのドヤパワーの上限 | 10 | 小 | 確認の画面（済み）・runner | 実行の仕組みの担当と画面（UI リニューアル） |
| 2 | スケルトン表示と先読み | — | 小〜中 | シェル（済み） | UI リニューアル |
| 3 | 3案の横並び | 4 | 中 | 各ツールの生成 API が複数の案を返すこと | UI リニューアル（バナー・コピー・スライドから） |
| 4 | 版の履歴と復元 | 5 | 中〜大 | 版を残す DB の表 | 設計を先に出す。スライド・見積もりから |
| 5 | エージェントの再生 | 7 | 中 | 作戦と実行の記録をサーバーに残すこと（今は端末だけ） | 実行の仕組みの担当と画面 |
| 6 | ブランドキット | 1 | 大 | 会社ごとの色・ロゴ・言葉づかいの DB と、各ツールのプロンプトへの受け渡し | 設計を先に出す。バナー・スライド・LP から |

画面に関わらない、または別の担当が向くもの:

- (2) インボイスの T 番号の自動照合、(3) 電子帳簿保存法の保存要件チェッカー: 経理のツール（収入・支出）の担当
- (6) レシピ: エージェントのレシピ（`AGENT_RECIPES`）と同じ仕組みです。実行の仕組みの担当
- (8) 社外向けレビューリンク、(9) LINE への通知: 共有と通知の仕組みが要るので、別に設計します

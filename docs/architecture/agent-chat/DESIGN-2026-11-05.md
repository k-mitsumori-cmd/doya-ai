## 決まり

- AI に保存の手段を渡さない。API `/api/agent/chat` は DB に業務データを書かない（使用回数の記録だけ）。
- 保存は、ツールの画面の本物の送信処理だけが行う。本人が確認カードか画面のボタンを押したときだけ呼ぶ。
- 完了の表示は、画面の送信処理が成功を知らせたあとだけ出す。失敗したら、失敗の内容と次にできることを出す。
- 欄に入れる値は、依頼の文から確かめられた値だけ（`groundValues`）。文に無い値は捨てて聞き返す。
- 種類・状態・開始日のような決まった値は、操作の定義（`fixed`）から入れる。AI には決めさせない。
- 計算（税、合計）は画面の今の処理のまま。
- AI のモデルは Claude Haiku 5.5（2026-11-06 本人の決定。Opus と Sonnet はチャットとエージェントに使わない）。1依頼 最大 約0.2円。
- ドヤパワーは減らさない。1人1日30依頼、全体1日300依頼（`consumeDailyQuota`）。聞き返しは AI を呼ばない。
- 旗は `AGENT_CHAT_ROLLOUT`（off / preview / all、既定 off）。off のときは今の画面と API が今のまま動く。
- 動きは位置と透明度が中心で、1つ 0.2〜0.5 秒。`prefers-reduced-motion` では飛ぶ値とカーソルを出さない。動きは実際の処理に合わせる。
- 売上の追加は単発の契約（`/income/contracts/new`、type=one_time、status=active、開始日は今日）。月の売上は `IncomeRevenueSchedule` から計算するので、手入力の請求書では月の売上に入らない。

### 段階2で足した決まり

- 請求書の下書き: 読み取るのは金額（税抜）・取引先・件名の3つ。件名は明細の1行目の品目にも入る（API が品目名を必須にしているため）。請求日は画面の今日のまま、支払期日は画面の今の決まり（取引先の支払条件）に任せる。AI には日付を読ませない（文に日付の言葉があるだけで、AI が計算した日付を信じてしまうのを避ける）。
- 支出の登録: 読み取るのは金額・取引先・名称の3つ。カテゴリ（SaaS）・周期（毎月）・開始日（今日）は画面の初期値のままで、確認カードに出す。違うときは本人が画面で直し、もう一度確認する。金額は税抜として入れ、「税込みだった」で画面の「入力した金額は税込です」を入れる（金額は割らない）。
- 取引先: 登録済みの同じ名前があればそれを選ぶ。無ければ、画面の「新しく登録する」に名前を入れる（保存のときに画面の今の処理が作る）。
- 確認カードを出したあとに、本人が画面の欄を直していたら、確認カードのボタンを押しても保存しない。画面の今の値で確認カードを出し直す（確認していない内容を保存しない）。
- 権限: 画面とサーバーが今していることをそのまま使う。支出の登録は担当者（manager）以上で、権限がない人には、値を入れる前に理由を出して止まる（`AgentBlocked`、フォームの `blocked`）。サーバー（API）が 403 を返す人は、確認カードのあとも保存できない。会話専用の判定は作らない。
- 失敗: 画面の送信が失敗を返したら、内容を出して「確認カードに戻る」を出す。完了は出さない。
- 支出管理をまだ始めていない人は、画面が出ないため「画面を開けませんでした。先に画面から始めてください」と出す。
- 新しい契約の画面は、会話が画面を進めている間だけ、売上予定の表が出る分の高さを先に取る（金額を入れたときの下のカードのずれを防ぐ）。

## 1. 何を変えるか

今の経営ホームでは、入力すると、語句の一致で各ツールの画面へ移るだけです（`src/app/(shell)/home/agent.ts`）。有料の AI は呼ばず、生成も外部送信もしません。

新しい体験では、次の4つを1つの画面の中で続けて見せます。

1. 依頼を送ると、ドヤくんが分析している様子を見せる。会社の情報・今月の数字・過去の成果物などの材料を並べて同時に読み、読み終わったものから作戦の材料になる。
2. ドヤAI がゴールを決め、今との差を出す（ゴール・今・差）。
3. 差を3つ前後の柱（チームのゴール）に分け、その下に ToDo を並べる（ToDo ごとに、使うツール・減るドヤパワー・所要の目安・「ドヤくんに任せる」）。
4. 「まとめて進める」を押すと、任せた ToDo を並べて進め、できた物（下書き）が順に出る。決まったことと下書きは作戦に残り、次は「続きを進める」から再開する。

ユーザーが「肝」と言っているのは、3と4（タスクに分けて、実際にこなすところ）です。演出は、その流れを分かりやすく、楽しく見せるためのものです。

## 2. 参考にしたもの

- **Addness（アドネス、https://hp.addness.com/ja）:** ユーザーが「Adonis」と書いていたのは、このサービスでした（2026-10-25 メインの確認）。公開ページから取り入れる点は、次の4つです。
  - ゴールを置き、ゴールと今の差を ToDo に分けて、ゴールの下に並べる。どの ToDo もゴールにつながるので、意味のない作業が出にくい。
  - 会社のゴール → チーム（部門）のゴール → ToDo の階層。
  - 決まったことと成果物をゴールに残し、次は前回の続きから動く（会話の全文を保存するわけではない）。
  - ToDo ごとに「AIに依頼する」ボタンがある。
  - ドヤAI への当てはめ: 作戦のカード＝ゴール、3つの柱＝チームのゴール、作業の一覧＝ToDo。ToDo ごとに「ドヤくんに任せる」を置く。下書きと決めたことを作戦ごとに残し、経営ホームの「続きを進める」から再開する（保存は段階3以降。表は実行の仕組みの担当と統括で決める）。
- **Manus の Wide Research（https://manus.im/en/blog/introducing-wide-research）:** 依頼を多数の小さな作業に分け、同じ能力を持つサブエージェントで並べて同時に進める仕組みです。この設計では、分析の場面で「材料を並べて同時に読む」様子と、実行の場面で「ToDo を3件ずつ同時に進める」様子に使います。まねるのではなく、ドヤAI の各ツールを、そのまま実行の部品にします。
- **「Adonis」という名前の会社（adonis.io）:** 医療の請求業務の会社で、今回の参考ではありません（聞き違いでした）。
- **キャラクターが主役の画面:** 背景をテーマパーク風にはしません。SaaS の白と青の画面のまま、ドヤくんを大きく置き、考える・作業する・できた、の3つの場面でポーズと動きを変えます。

ユーザーが別のツールを指していた場合は、名前を教えてもらい、この章を直します。

## 3. 画面の流れ

| 場面 | 見せるもの | ドヤくん | 目安の時間 |
|---|---|---|---|
| 0. 入力 | 「続きを進める」（前回の作戦・ToDo の進み具合・残り）と、新しい依頼の入力欄・依頼の例 | あいさつ（hello） | — |
| 1. 分析 | 読む材料の札が1枚ずつ流れ込み（Animated List）、それぞれに進み具合の棒が付いて同時に進む。1280px では札からドヤくんへ光の線が流れる（Animated Beam）。読み終わった札にはチェック。考えたことが、ぼかしから1行ずつ出る（Blur Text / Text Effect） | 考え込む（ponder）。後ろの光がゆっくり脈打つ | 材料を読み終わるまで（見本は約5秒） |
| 2. ゴール・柱・ToDo | ゴールのカード（今・ゴール・差の数字は数え上げ＝Number Ticker）→ 柱（チームのゴール）→ ToDo の木。順にふわっと出る（Animated Group）。ToDo ごとに「ドヤくんに任せる」と減る量 | 指さし（point） | — |
| 3. 確かめ | 「合計で減るドヤパワー」と、今の残り・実行後の残りを出し、1回だけ確かめる | 指さし（point） | — |
| 4. 実行 | 任せた ToDo を3件ずつ同時に進める。進んでいるカードだけ縁を光が回る（Border Beam）。終わったら小さなチェックが描かれる。できた下書きは上に積まれていく | 作業（working） | ToDo による（数十秒〜数分） |
| 5. 完了と記憶 | できた物の一覧と、「作戦に残しました（決まったこと・下書き）。次は続きを進めるから再開できます」 | できた（success） | — |

- 分析の札は、実際に読んでいる材料に合わせて出します（実行の仕組みが返す「読んでいる材料の一覧と進み具合」をそのまま描く）。作り話の進み具合は出しません。答えが早く返っても、最短1.5秒は見せます。
- 考えたこと（Blur Text の行）も、作戦づくりの答えに入っている「理由」の文から出します。
- 実行中は、画面を移っても進みます。経営ホームに戻ると、続きから見えます（段階3以降。§7）。

## 4. 演出の決まり

- **洗練された動きにする（2026-10-25 ユーザーの評価で方針を変えた）:** 揺れ・集中線・画面全体の紙吹雪のような「お祭り」の派手さは使いません。動かすのは、意味のある所だけです（材料が流れ込む・光が流れて材料がドヤくんに集まる・数字が数え上がる・進んでいるカードの縁が光る・終わったらチェック）。ドヤくんのポーズは、2枚を重ねてふわっと入れ替えます。
- **動きを止める設定:** `prefers-reduced-motion: reduce` のときは、すべての動きを止め、最後の状態（読み終わった札・数字の最後の値・チェック済み）をそのまま出します。待ち時間も挟みません。
- **全画面にしない:** 読み込みの全面表示や、画面全体の色が変わるフラッシュは出しません。演出は、ホームの中の決まった枠（ステージ）の中だけで動きます。枠の高さは場面ごとに決めておき、場面が変わっても下の行がずれないようにします。
- **絵文字を使わない:** 絵は、既存のドヤくんの絵（`public/character/*-512.webp`）を使います。足りないポーズは、Codex の定額の画像生成で作ります。従量の画像 API は使いません。
  - 2026-10-25 に5つのポーズ（ponder・throw・launch・run・finish）を作りました。作り方とプロンプトは `docs/design/images/home-agent/PROMPTS.md` にあります。
- **音は出さない:** 最初の段階では、効果音を入れません。

## 5. 戦略とタスクの作り方

### 戦略（有料の AI を使う）

- 依頼と、経営ホームが読める事実（今月の数字・使っているツール・会社の情報）を渡し、戦略を JSON で返してもらいます（`geminiGenerateJson`）。
- 返す形の例:

```json
{
  "goal": "新サービスの問い合わせを月20件にする",
  "period": "4週間",
  "pillars": [
    { "id": "pr", "name": "広報", "why": "...", "tasks": [
      { "tool": "seo", "action": "seo.article", "title": "比較記事の下書き", "units": 1, "minutes": 6 }
    ] }
  ]
}
```

- `tool` と `action` は、決まった一覧（`src/components/shell/tools.ts` と `src/lib/doya-power/costs.ts`）の中からだけ選ばせます。一覧に無い値が返ったら、そのタスクは捨てます。
- 減るドヤパワーは、AI の答えではなく、`costs.ts` の表から計算します（AI に数を決めさせない）。

### タスクの実行

- 各タスクは、今ある各ツールの生成の API を、サーバーから呼んで進めます（バナー・記事・ペルソナ・スライドなど）。新しい生成の仕組みは作りません。
- できる物は、すべて「下書き」です。外部への送信・公開・取り消せない操作（メールを送る・広告を出す・記事を公開する）は、エージェントが自動では行いません。下書きの横に「確認して送る」のボタンを出し、押すのは人です。
- タスクの間に順番がある場合（ペルソナを作ってから記事を書く、など）は、戦略の JSON に `after` を持たせ、前のタスクができてから始めます。

## 6. 費用の見せ方

- 戦略を作る1回目も、有料の AI を使います。そのため、入力欄の下に「戦略を作るのに ◯ 減ります」と小さく出します（新しい操作の名前 `agent.plan` を `costs.ts` に足す案。量は統括とユーザーで決める）。
- タスクの一覧では、各タスクに減る量の札（`ShellCostBadge` と同じ見た目）を付けます。チェックを外すと、合計がその場で変わります。
- 「まとめて進める」を押すと、画面の中の確かめの欄を出します（ブラウザの確認の窓は使いません）。
  - 合計で減るドヤパワー
  - 今の残り
  - 実行したあとの残り
  - 足りないときは、足りない量と次の回復の時刻（`LowPowerNotice` と同じ）を出し、実行のボタンを押せなくします。
- 確かめは1回だけです。タスクごとに何度も聞きません。
- 失敗したタスクは、台帳の決まりどおり、減った分を戻します（`withDoyaPowerCharge` と同じ）。完了の画面に「失敗して戻した分」も出します。

## 7. 段階の分け方

| 段階 | 中身 | 有料 API | 出す相手 |
|---|---|---|---|
| 1 | 動く見本だけ（この設計書と一緒に出す。実際の生成はしない） | 使わない | ユーザーの確認用 |
| 2 | 経営ホームに、入力 → 考える演出 → 戦略 → タスクの一覧まで。実行のボタンは、各ツールの画面へ移るだけ | 戦略づくりだけ（Gemini のテキスト） | ユーザーだけ（旗の preview） |
| 3 | 「まとめて進める」で、各ツールの生成を順に呼び、下書きを出す。実行の記録を残し、画面を移っても続きが見える | 戦略づくりと各ツールの生成 | ユーザーだけ |
| 4 | 並べて進める数を増やす。キャラクターの動きを Lottie か Rive で作り込む | 同上 | 全員（旗の all） |

- 段階3では、実行の記録の表（例 `home_agent_runs` と `home_agent_tasks`）が要ります。これはスキーマと本番 DB の変更なので、段階2が済んだあとに、案を統括に出して、ユーザーの承認を取ってから足します。
- 開発中の確かめで有料 API を回すときは、その前に「モデル・回数・見込み額」を出して、ユーザーの承認を取ります（CLAUDE.md の決まり）。

## 8. 旗と出す相手

- 旗は、実行の仕組みと同じ `AGENT_ORCHESTRATION_ROLLOUT`（off / preview / all）の1つだけです。`HOME_AGENT_ROLLOUT` は使いません（2026-10-25 ユーザーの決定。agent-orchestration の DESIGN.md §12）。旗が off なら、今の経営ホームのままです。
- 実行の記録（`AGENT_RUNS_STORE`）は、表を足すまで off です。そのあいだ、「続きを進める」は端末に残した続きを使います。
- preview のときは、`UI_PREVIEW_EMAILS` に書いた人（最初はユーザーだけ）にだけ出します。
- 旗が off のときは、戦略づくりの API も呼びません（サーバーで先に旗を見る）。

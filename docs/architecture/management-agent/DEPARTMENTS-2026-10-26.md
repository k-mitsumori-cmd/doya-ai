# 部署ごとの入口（ドヤマーケAI・ドヤセールスAI・ドヤ人事AI・ドヤ管理AI）の設計

2026-10-26 作成。ユーザーの決定（メイン経由）を、画面と仕組みに落とした設計です。動く見本: https://claude.ai/artifact/E9nBXTNAyE2DHsnjv8vRwD （非公開。375px と 1280px で確かめた）

## 1. 決まったこと（2026-10-26 ユーザー）

- 製品の名前は「ドヤAI」のまま1つです。契約も料金も1つです。
- その中に、部署ごとの入口を4つ作ります。

| 入口 | 部署 | ツール |
|---|---|---|
| ドヤマーケAI | マーケティング | AIO・記事作成・バナー・広告画像・ペルソナ・インタビュー・AI質問リンク・ポップアップ・展示会 |
| ドヤセールスAI | 営業 | 営業管理・商談準備・AI商談・リスト・スライド・見積もり |
| ドヤ人事AI | 人事 | HR・面接官・社内インタビュー・勤怠 |
| ドヤ管理AI | 経理・管理 | 収入管理・支出管理・プロマネ・請求（収入管理の中） |

- カンニング（Web会議の回答の提示）は、どの部署の入口・メニュー・例にも出しません。ベータとして隠す決定（ユーザー）のとおりです（2026-10-26 メインの確認）。
- 見積もりは、今の区分「経理・バックオフィス」から、ドヤセールスAIへ移ります。

## 2. 仕組み

1. **はじめの設定で、主に使う部署を選ぶ（複数可）。** 経営ホームと左のメニューは、選んだ部署のツールを先に出します。
2. **部署ごとのホーム。** その部署の数字と、依頼の例だけを出します。URL は `/home?dept=sales` の形にし、新しいページは増やしません。
3. **社員ごとの部署。** 権限の仕組みに「部署」を足します。営業の人にはドヤセールスAI、経理の人にはドヤ管理AIを初めに見せます。社長と管理者は全部を見ます。
4. **「ドヤくんに頼む」の例と作戦を、部署ごとに変えます。** 例: セールスなら「商談の準備をまとめて進めたい」、マーケなら「今月の記事を3本進めたい」。
5. **ほかの部署のツールも使えます。** 「すべて」のタブと ⌘K の検索から開けます。部署で使えなくすることはしません（表示の順番を変えるだけ）。

## 3. 正本と置き場所

- 部署の表の正本は `src/lib/departments.ts` の1か所だけにします（id・名前・ツールの id の並び）。`services.ts` には持たせず、`tools.ts` の区分（stage）は、旗が on のときこの表から決めます。
- 部署の id: `marketing`・`sales`・`hr`・`admin`。
- 「主に使う部署」の選び方の優先:
  1. 社員の部署（権限の担当が足す。メンバーごとの `department`）
  2. はじめの設定で選んだ部署（新料金の担当が持つ、はじめの設定の画面）
  3. どちらも無ければ、最近使ったツールの部署
  4. それも無ければ、4つを今の順で並べる
- 社長と管理者は、主の部署があっても全部を出します（順番だけ変える）。

## 4. 旗

- `DEPARTMENTS_ROLLOUT`（off / preview / all、既定 off）。今の旗と同じ形で、判定はサーバーだけです。
- off のときは、今のメニュー（マーケティング・営業（セールス）・採用・人材管理・経理・バックオフィス）のままです。

## 5. 画面

- **左のメニュー**: 区分の見出しを「ドヤマーケAI」などの入口の名前にします。主の部署を先頭に置き、ほかの部署は畳んで「ほかの部署」にまとめます（押せば開く）。
- **スマホの下のタブ**: 「ホーム・主の部署・すべて・アカウント」にします。
- **経営ホーム**: 上に部署の切り替え（チップ: すべて・マーケ・セールス・人事・管理）を置きます。選ぶと、数字・例・よく使う操作・最近の作業が、その部署の分だけになります。
- **⌘K の検索**: 部署の名前でも探せるようにします（「セールス」で営業のツールが出る）。

## 6. 分担（ファイルが重ならないように）

| 担当 | 受け持つもの | 触るファイル |
|---|---|---|
| UIリニューアル（このセッション） | 部署の表・旗・メニューの並び・経営ホームの部署の切り替え・ドヤくんの例 | `src/lib/departments.ts`（新）、`src/lib/departments/flag.ts`（新）、`src/components/shell/tools.ts`・`AppShell.tsx`、`src/components/home-agent/*`、`src/app/(shell)/home/*` |
| 権限の担当（local_21ded680） | メンバーごとの部署（表の列・API・管理画面での設定） | 権限の正本のファイル。部署の値は `departments.ts` の id を使う |
| 新料金の担当（local_f6301b2d） | はじめの設定の画面で「主に使う部署」を選ぶ | はじめの設定の部品。保存した値は、UI が読む API（または cookie）で渡す |

- 部署の値の受け渡しの形は、`{ primary: DepartmentId[]; all: boolean }` にそろえます（all は社長・管理者）。
- DB の表を変える（部署の列を足す）ときは、`doya-db-push` の手順と、統括を通したユーザーの承認が要ります。段1では、DB を変えずに、はじめの設定の選択を cookie に残し、メニューの並びだけを変えます。

## 7. 段階

| 段階 | 中身 | DB |
|---|---|---|
| 1 | 部署の表・旗・メニューの見出しと並び・経営ホームの部署の切り替え・部署ごとの例 | 変えない（選択は cookie） |
| 2 | はじめの設定で部署を選ぶ（新料金の担当） | 変えない |
| 3 | 社員ごとの部署（権限の担当） | 列を足す（承認のあと） |
| 4 | 部署ごとの数字と、最近の作業 | 変えない |

# 会社とツールの連携解除を維持する

2026-11-09、利用者は「解除を維持し、同じ会社への自動再連携を止める」を選択した。購入席の制限と自動請求の禁止は継続する。

解除すると、その会社・ツール・組織に限る自動連携停止記録を既存の SystemSetting に残す。次の役割確認で同じ会社への連携を再作成しない。別会社の連携を一律に止めない。停止記録に期限はなく、未知の値でも記録の存在を優先して自動連携を止める。

停止記録、連携削除、監査記録は同じSQLトランザクションで保存する。会社オーナーであることを現在の行から再確認し、失敗した場合は全変更を戻す。自動連携も会社→組織のロック順を使い、待機中に保存された停止記録を読み直す。

会社連携と課金上の帰属は別に検証する。解除しても、作成者が現在の唯一のオーナーであると確認できる組織は既存の人数集計に残す。会社内の既存メンバーには、未連携組織の既存ルールに従って会社の役割上限を維持する。したがって会社ゲストが解除だけで操作権限を得ることはない。会社に参加していないツール操作メンバーは引き続き人数に数える。

解除により帰属先が変わる場合は、変更前後の会社・オーナーの席管理を固定し、変更後の実集計を確認する。席不足、購入人数不明、変更処理中、移管後の支払者を確認できない場合は解除を保存しない。FREEの既存枠、旧PROの既存枠、Teamの購入席を互いに置き換えない。プロフィール登録、会社メンバー登録、User.plan変更、Stripe呼び出し、自動増席は行わない。未連携HR移管時の支払者はこの変更で決定しない。

会社の管理者以上かつ対象ツールの最上位権限を現在も持つ人は、既存POSTから明示的に再連携できる。購入席を確認し、再連携・停止記録削除・監査記録を同じ取引で保存する。再連携に失敗した場合も停止記録を維持する。

検証は、実APIとPrismaを使う私有Unixソケット上の新規PostgreSQLで行う。セッションと最初の会社文脈は合成データであり、本人の実OAuthや実際の購入・返金・メール送信の確認とは区別する。広範な監査と他の帰属変更writerの検証は継続中。

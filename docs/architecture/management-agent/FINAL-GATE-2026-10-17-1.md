## 検算メモ

- **§7.4 数値例**: grant+100→100、reserve−20→80、consume+5→85、reserve−30→55、release+30→85、reserve−10→75、consume+0（P=10 月複製）→75、refund+5→80、11 月 grant+100→100、席+1 で付与なし。**全行一致**。月またぎ（reserve 行の period 複製）・席変更（付与なし）・旧契約（3 段判定＋手順 4）・ロールバック（Checkout 入口のみ）は仕様どおり動く。返金は FIN-09、再 reserve は FIN-04。
- **§8.6 到達性**: queued / running / waiting_approval / paused / done / failed / canceled は終端に到達可能。**`planning` のみ、リース期限切れ時に拾う主体が無い**（FIN-01）。`paused(company_suspended)` は復帰主体が未定義（FIN-12）。リース＋フェンス（`withAgentRunExecution`）は SeoJob L41-48 の複製で、token 不一致で全書き込みが止まるため「DB 上の二重実行」は起きない。外部副作用の二重化は `unknown_outcome`→人の確認で止まる（自動再試行なし）。

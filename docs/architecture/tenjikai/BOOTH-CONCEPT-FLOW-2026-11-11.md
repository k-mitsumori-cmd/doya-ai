# ドヤ展示会：戦略から画像までの作り直し（2026-11-11）

本人の指摘（2026-11-11）を受けた設計です。BOOTH-DESIGN-KIT-2026-10-29.md の 4 章（色面だけのデザイン）は、この文書で置き換えます。

## 1. 本人の指摘

- ブースの背面などの画像が出ない。出ても質が低い。
- 「ブースのデザインの決まり」の3つの案が、ほとんど同じに見える。
- 3D 完成予想図が、作った案と合っていない。
- 先に全体の戦略と完成のイメージを決め、そのあとで画像を作る順にしたい。
- 画像は、質の高いものを作らないと意味がない。

## 2. 原因（コードと本番で確かめた）

| 指摘 | 原因 | 場所 |
|---|---|---|
| 画像が出ない | 1人1日の上限が7枚。1つのブースには面と制作物で15枚前後が要るので、途中で上限に当たり、残りの面が作られない。2026-11-11 の本番で、本人の残りは 0 枚だった | `image-quota.ts`、環境変数 `TENJIKAI_IMAGEGEN_PER_USER_DAILY`。全体の1日の上限は既定 500 円（約23枚） |
| 画像の質が低い | 指示文が「帯1本と円1つの、平らな色面だけ。写真・イラスト・3D・人物・製品の画面は描かない」と決めている。10月29日に、面をそろえるために決めた形で、絵としての見どころが無い | `design-kit.ts` の `kitBlock` と `buildDesignPrompt` |
| 3つの案が同じ | 案の違いが、色の面積の比率・帯の高さ・円の大きさだけ。色も形も同じ | `design-kit.ts` の `KIT_VARIANTS`、`DesignKitStudio.tsx` |
| 3D 完成予想図が合わない | 画面の「3D完成予想図」は、コードで組んだ箱の表示と、固定の見本の写真（`/tenjikai/booth-sample.webp`）。案ごとの完成予想図を AI で作る処理（`buildBoothRenderPrompt`）は、画面から呼ばれていない | `BoothStudio.tsx`、`imagegen.ts` |
| 戦略が先に無い | 文章の AI が作るのは、案の名前・コンセプト・動線の文だけ。デザインの方向は作っていない。レイアウトの3案（オープンデモ型・シアター型・商談重視型）は固定 | `ai.ts`、`engine.ts` の `generateBoothPlans` |

## 3. 新しい流れ

1. 条件を入れる（今のまま）。
2. 戦略を作る（文章の AI。`/api/tenjikai/generate` に足す）。
   - 出展の狙い、来てほしい人、通路から3秒で伝える一言、ブースで体験してもらうこと。
   - デザインの方向を3つ。3つは、見た目の作り方そのものが違う（4 章）。
3. 方向を1つ選ぶ。選ぶ画面には、方向ごとの「色・絵の作り方・素材・照明・見出し」を文と色見本で並べる。ここまでは画像を作らない。
4. キービジュアルを1枚作る（背面壁の中央。これが見本になる）。本人が見て、良ければ確定する。作り直しもできる。
5. 残りの面と制作物を、キービジュアルを参照して作る（今の「見本を参照」の仕組みを使う）。
6. 完成予想図を作る。3D の表示を画像にしたもの（配置と寸法）と、キービジュアル（絵柄）の2枚を参照に渡す。案ごとに作り、3D 完成予想図の欄に出す。固定の見本の写真は、まだ作っていないときだけ「見本」と書いて出す。
7. 書き出す（今のまま）。

作る前に、要る枚数・減るドヤパワー・きょうの残りの枚数を出す。残りが足りないときは、作り始める前にそう伝え、どの面から作るかを選べるようにする。

## 4. デザインの方向（3つ。絵の作り方が違う）

方向は `ArtDirection` として持つ。文章の AI が、サイトの内容と目的に合わせて、名前・狙い・キービジュアルの題材・見出しを書く。絵の作り方の型は、次の3つから1つずつ使う（3つとも必ず出す）。

| 型 | 絵の作り方 | 向く目的 |
|---|---|---|
| `photo` 実写 | 人や利用の場面、製品を使う手元などの写真のような絵を、面いっぱいに使う。見出しは写真の上の色の帯に置く | 信頼・導入の実感を伝えたい |
| `graphic` 大きな文字と色面 | ブランドの色の大きな面と、太い見出し。幾何の形を大きく使う。遠くから読める | 通路で足を止めたい、認知 |
| `world` 世界観 | 立体のイラストや、光と奥行のある空間の絵で、サービスの世界を1枚で見せる。製品の画面の見せ方も含む | デモ・体験に引きこみたい |

どの型でも守ること（10月29日の試しで分かったことを残す）。

- 色は、決まりの5色を主に使う（`BoothDesignKit.palette`）。写真や立体の絵でも、全体の色みをこの色に寄せる。
- 画像に描く文字は、確定した見出し1つだけ（1行12字・2行まで）。それ以外の文字・数字・ロゴ・寸法線は描かせない。長い文・QR・ロゴは画面の側で重ねる。
- 指示文に、寸法と割合の数字を書かない（画像に寸法線が描かれるため）。
- 灰色の額縁は、今の切り落とし（`grayFrameInset`）を使う。
- 実在の人物・実在のロゴ・認証マークは描かせない。

`BoothDesignKit` に `direction`（型・名前・狙い・題材・絵の調子の文）を足し、`version` を 2 にする。古い保存（version 1）は `graphic` として読む。`kitBlock` は、型ごとの「絵の調子」の文を出し分ける。「帯1本・円1つ・平らな色面だけ」の文は `graphic` の型にだけ残し、それも「大きな幾何の形を1〜2つ」に緩める。

## 5. 画像の質

- モデルは今のまま（`gemini-3-pro-image`、統一ディスパッチャ）。解像度は 2K のまま。4K は単価が上がるので、本人が決めるまで使わない。
- キービジュアルの指示文は、次の順に書く。役割 → デザインの方向（型・題材・構図・光・素材）→ 色 → 文字 → 禁止。型ごとに、構図と光の言葉を具体的に書く（例: 実写なら「自然光、浅い被写界深度、人物は後ろ姿か手元」）。
- 完成予想図は、展示ホールに建った写真のような絵にする。参照は、3D の表示の画像とキービジュアルの2枚。

## 6. 上限

- 1つのブースを作りきれる枚数にする。目安は、面の数＋制作物6＋完成予想図1＋作り直しの余裕で、1日 30 枚。
- 変えるのは環境変数（`TENJIKAI_IMAGEGEN_PER_USER_DAILY`、`TENJIKAI_IMAGEGEN_DAILY_LIMIT_YEN`）で、本番の設定の変更になる。本人の承認のあとに行う。コードの既定値は変えない。
- いまは本人のアカウントだけに出している（`TENJIKAI_IMAGEGEN_ROLLOUT` は変えない）。

## 7. 実装の段

| 段 | 中身 | 有料の呼び出し |
|---|---|---|
| S1 | `design-kit.ts` に方向（3つの型）を足す。`kitBlock`・`buildDesignPrompt`・`buildBoothRenderPrompt` を型ごとに書き分ける。テストを足す | なし |
| S2 | `/api/tenjikai/generate` と `ai.ts` に、戦略と3つの方向を足す（失敗したら、サイトの解析から作った下書きの3方向で埋める） | 文章の AI（利用者の操作のときだけ） |
| S3 | 画面: 「デザインの決まり」を「戦略とデザインの方向」に作り替える。キービジュアルを先に作って確定する段を足す。作る前の枚数の表示 | 利用者の操作のときだけ |
| S4 | 完成予想図: 3D の表示を画像にして、キービジュアルと一緒に参照に渡す。案ごとに保存して出す。参照を2枚受けられるよう `/api/tenjikai/image` を直す | 利用者の操作のときだけ |

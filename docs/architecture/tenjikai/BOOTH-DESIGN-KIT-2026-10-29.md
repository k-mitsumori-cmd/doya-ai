## 1. ユーザーの指摘

展示会ツールで作った画像と動画が、ばらばらで、統一感がない。

- 展示会の例を大量に調べ、全体で共通の色と見た目にする方法を、アイデアとして集めてほしい。
- その方法を、ツールの仕様にしてほしい。
- 画像を作っている待ち時間も、ドヤくんが作っているような絵にして、遊び心を入れてほしい。

## 2. いまばらばらになる原因（コードを読んで特定した）

## 3. 調べた結果の要約

くわしい表と出典の URL は `docs/research/tenjikai-booth-2026-10-29/` にある。事例は、制作会社や展示会メディアの記事から読み取った内容で、写真は見ていない。成果の数字は自己申告なので、集めていない。

### 3.1 国内の実例（93 件）で多かった型

1. 主色1つと白（または黒）に絞る型。約 20 件。白と青、黒と緑、オレンジと白など。
2. 会社の色を、壁・床・カウンター・小物まで広げる型。約 12 件。
3. 世界観を、素材・造形・備品・照明まで貫く型。約 11 件。
4. 会社名やロゴを、高い位置・大きさ・立体・内照式で遠くから見せる型。約 11 件。
5. 面の役割を分ける型（壁と吊り看板は遠く、展示台と卓上は近く、手元は配布物）。約 12 件。
6. 円と丸みで、入りやすさと形をそろえる型。約 10 件。
7. 照明と映像を、ブースの色や世界観に合わせる型。約 10 件。
8. 卓上や配布物まで、同じ色とテーマにそろえる型。約 6 件。

国内で情報が薄かった所は、書体、クリアファイルと名刺、映像の作りの3つ。この3つは、海外の事例と一般論で補った。

### 3.2 海外の実例（36 件）で多かった型

- 主役の色1つと白の土台に、少量の差し色を足し、面積の比率を決める型（Banner Engineering は、白を約 80%、黒を 5%、ブランドの黄色を 10% までと決めている）
- 1つの物語を、制服・小道具・配布物・映像まで貫く型
- ロゴや基本図形を、模様・立体・什器に繰り返す型（Figma の Config は、四角・円・多角形を大きな図形にし、部品として管理している）
- 組み替えられる骨組みに、入れ替えるグラフィックを乗せる型
- 遠目・中距離・近距離で、面の役割を分ける型
- 映像の動きを少数の原則で決め、静止画と並行して作る型
- 配布物・印刷物・Web も同じ色・書体・ロゴの規則に従わせる型
- 引き算（余白）で主役を立てる型

### 3.3 失敗の例（国内と海外で共通）

要素ごとにデザインが違う。色が強すぎる、色数が多い。文字が小さすぎる。パネルに情報を詰め込む。画像を1枚ずつ承認し、全体で見ない。

## 4. 仕様：ブースのデザインの決まり（Booth Design Kit。以下 BDK）

最初に BDK を1つ決める。そのあとで作る画像・書類・動画は、すべて同じ BDK から作る。

### 4.1 BDK の中身

```ts
// 案。src/lib/tenjikai/design-kit.ts に置く（新規）
export interface BoothDesignKit {
  version: 1
  brand: { name: string; domain: string; tone: string }
  /** 値の出どころと確からしさ。画面に出して、利用者が直せるようにする */
  provenance: Record<'primary' | 'dark' | 'accent' | 'font' | 'logo', { from: 'theme-color' | 'css-variable' | 'logo-image' | 'dom' | 'ai' | 'user' | 'default'; confidence: 'high' | 'mid' | 'low' }>
  palette: {
    primary: string // 主色。見出しの帯・大きな面
    dark: string    // 暗色。文字と、濃い面
    accent: string  // 差し色。小さな面だけ
    paper: string   // 紙の色。白か、ごく薄い色
    mist: string    // 薄い補助色。下の面・枠
    /** 面積の目安の比率（合計 1） */
    ratio: { paper: number; primary: number; dark: number; accent: number }
  }
  type: { family: string; weights: { head: 800 | 900; sub: 700; body: 500 }; /** 距離ごとの文字の高さ（mm） */ sizeMm: { far: number; mid: number; near: number } }
  logo: { svg?: string; png?: string; wordmark: string; clearSpace: number /* ロゴの高さに対する余白の倍率 */; places: ('top-left' | 'center' | 'bottom-right')[] }
  motif: { shapes: ('band' | 'circle' | 'dots')[]; bandAngleDeg: number; bandHeightRatio: number; circleDiameterRatio: number; circleAnchor: 'right-bottom' | 'left-bottom' | 'center' }
  zones: { headBandRatio: number; footBandRatio: number }
  imageTone: 'flat-illustration' | 'photo' | 'monochrome'
  motion: { enterMs: number; holdMs: number; exitMs: number; easing: string; transition: 'slide' | 'fade' | 'wipe'; endCardMs: number }
}
```

### 4.2 決め方（URL から BDK の下書きを作り、利用者が確かめて確定する）

1. 色・書体・ロゴは、ページの実測から取る。取る順番は、`theme-color`、CSS の変数（`--primary`・`--accent`・`--brand`）、ロゴ画像の主な色、要素の色の出現数。AI には「口調」と「業種」の推定だけを任せる。AI に色や書体を作らせない（調査で、文章だけを読む AI は色や書体を作り話にすることがあると分かった）。
2. 取れなかった値は、取れた値から規則で決める（4.3）。何から決めたか（`provenance`）を、画面に出す。
3. 見本のボードを、コードで3案描く（AI を呼ばないので無料）。3案は、色の分け方が違う（主色が大きい案、紙が大きい案、暗色が大きい案）。利用者が1つ選び、色・書体・ロゴを直して確定する。
4. 確定した BDK は、プロジェクトに保存し、版を持つ。直したら、作り済みの画像に「古い決まりで作った」と印を付け、作り直せるようにする。

### 4.3 色の規則

- 役割は5つ（主色・暗色・差し色・紙・薄い補助色）。使う色はこの5つだけにする。
- 面積の初期の目安は、紙 60%、主色 25%、暗色 10%、差し色 5% 以内。Banner Engineering の例（白 約 80%、黒 5%、黄色 10% まで）を参考にした。数字は実際の出来を見て調整する。
- 差し色は、小さな面だけ。大きな面に使わない。
- 文字の色は、背景との比が 4.5 以上（大きい文字は 3 以上）になるよう、暗色か紙を選ぶ。足りないときは、文字の下に帯を敷く。
- 取れた主色が、黒・白・灰色に近いときは、差し色を主役にして、主色を暗色に回す。
- 主色が薄すぎるとき（明るさが高く、彩度が低い）は、暗色の側に寄せた版を作り、2つを見せて選んでもらう。
- 画面の色と印刷の色はずれる。書き出しの前に「印刷では色が変わります」と出し、色見本での確認をすすめる。

### 4.4 書体と文字（文字も含めた完成品の画像にする）

2026-10-29 の方針: 画像は、見出しなどの文字も含めた、完成品の1枚にする（前の版の「文字をコードで重ねる」は、3D の上で読めない・切れる原因だったので、主役を入れ替える）。ただし、AI は日本語の文字を崩すことがあるので、次の仕組みで守る。

- 書体は、日本語のゴシック体の雰囲気を1つに決める（太く、字間は広め、角は丸めない）。指示文の中で、毎回同じ言葉で書く。見本（マスター）を参照画像に渡すと、書体の雰囲気も引き継がれる。
- 文字の高さは、見る距離で3段にする。遠く（10m 以上）はロゴと色の面だけで、小さな文字を置かない。中距離（3〜10m）は見出し1つ（高さ 150mm 以上。背面壁の中央は 250mm 以上）。近く（2m 以内）は本文と QR コード。
- 画像に描かせる文字は、短いものだけにする。見出しは 12 字以内（1〜2 行）、補足は 20 字以内。1つの面に、文字のかたまりは最大 2 つ。
- 長い文章、数字の表、QR コード、ロゴは、画像に描かせない（崩れる、または作り話になる）。これらは、画像に空けた場所に、コードで重ねる。QR コードとロゴは、実物のデータをそのまま使う。
- 文字は、画像の端から 8% 以上離す（安全領域）。立体表示で面を切り出しても、文字が切れない。
- 面ごとの見出しの文字列は、画像を作る前に確定する。利用者が、誤字と長さを確かめる。確定した文字列を、一字も変えずに引用符つきで指示文に入れる。
- 作ったあとに、文字を自動で確かめる（5 章の手順 6）。崩れていたら作り直し、それでもだめなら、その面だけ「コードで文字を重ねた版」にする。

### 4.5 ロゴ

- 置く場所は、左上・中央・右下の3か所に限る。ロゴの周りに、ロゴの高さの 0.5 倍の余白を空ける。
- ロゴ画像は、取れたら使い、取れなければ利用者に上げてもらう。取れないままのときは、ブランド名の文字（ワードマーク）を、決めた書体で置く。ロゴを AI に描かせない。
- ロゴの形を柄に使う案は、ロゴが取れたときだけ出す（海外の事例で多い型）。

### 4.6 絵柄の言葉（モチーフ）

- 形は「帯」「円」「点の格子」の3つから、最大2つ選ぶ（初期は帯と円）。
- 帯: 角度は 12 度で固定。幅は面の高さの 18%。1面に1本。
- 円: 直径は面の短い辺の 40%。中心は右下寄りに置く。1面に1つ。
- 絵の調子は、フラットなイラストで固定する（写真・3D は使わない）。
- 隣の面とつながって見えるよう、帯と円は面の端で切れてよい。
- 図形は、コード（SVG）で描ける。AI に頼むのは、図形に質感を足したいときだけ。初期の版は、図形をすべてコードで描き、AI の画像生成を使わずに、ばらつきを 0 にすることも選べる（9 章の判断の1つ）。

### 4.7 面の型（レイアウト）

すべての面は、次の4つの型のどれかにする。型の外のレイアウトは作らない。

| 型 | 使う面 | 構成 |
|---|---|---|
| ヒーロー | 背面壁の中央、吊り看板 | 上 30% は主色の帯（ロゴと見出し）。中央に円。下 20% は紙の色の無地 |
| 訴求 | 背面壁の左右、ロールアップ | 上 30% は暗色か主色の帯（見出し1つ）。中央に帯。下 20% は無地 |
| 数字 | 側面壁 | 上 30% に見出し。中央に大きな数字3つ（コードで描く）。下に QR コード |
| 案内 | カウンター、扉の面 | 主色の面にロゴ1つ。足元は暗色 |

### 4.8 成果物ごとの当て方

| 成果物 | 型 | 文字・ロゴ・QR | 背景の作り方 |
|---|---|---|---|
| 背面壁（中央・左右） | ヒーロー・訴求 | 見出しと補足は画像に描かせる。ロゴは実物をコードで重ねる | AI（文字入りの完成画像） |
| 側面壁 | 数字 | 見出しは画像。数字3つは、コードで描いて重ねる（数字を AI に作らせない） | AI の背景と、コードの数字 |
| ロールアップ | 訴求を縦に | 見出しは画像。QR とロゴはコードで重ねる | 背面壁の見本から派生 |
| 吊り看板 | ヒーロー（ロゴだけ） | ロゴを実物で置く | 主色の面（コードの SVG） |
| カウンター、扉の面 | 案内 | 短い案内文は画像。ロゴは実物 | 主色の面 |
| チラシ（A4） | 訴求を紙面向けに | 見出しは画像、長い文・特長・料金・QR はコードで組む | 背面壁の見本から派生 |
| クリアファイル | ヒーロー | ブランド名は画像、ロゴは実物 | 背面壁の見本から派生。中央は薄く |
| 名刺サイズの QR カード | 案内 | 案内文と QR は、コードで組む | 主色の面 |
| モニター用の動画 | 4.9 | カットごとの見出しは、完成画像（文字入り）を動かす | 文字入りの静止画を動かす |
| 完成予想図 | — | 面の画像を貼った 3D を、そのまま描く | AI でフォトリアルに描かせるときは、面の画像を参照として渡し、色の指定は BDK の言葉で入れる |

### 4.9 動画（モニターのループ）の規則

- 3〜6 カット。無音で、文字だけで意味が通るようにする。1カットは見出し 12 字、補足 20 字まで。各カットの静止画は、文字入りの完成画像（4.4）を使い、動かすのは画像全体だけ。文字を `opacity` で出し入れしない（動きの途中で、薄い文字が残るため）。
- 動きは、BDK の `motion` から読む。入場・保持・退場の長さ、動きの種類（スライドか、フェードか）は1種類に固定する。全カットが同じ。
- 最後の1カットは、ロゴ・会社名・ブース番号・QR コードの固定のカード。ループの継ぎ目の背景色は、先頭と同じにする。
- 画面の端から 5% は、重要な要素を置かない。
- 作り方は、AI の動画を使わず、決まりに沿った文字入りの静止画をコードで動かす（ゆっくり拡大、スライド）。画風がぶれず、従量課金の動画 API も要らない。Remotion などの動画の部品か、ffmpeg で書き出す。
- MiniMax などの動画 API を使う場合は、従量課金になる。回す前に、モデル・長さ・本数・合計の見込み額をメインに出し、承認をもらう。

### 4.10 指示文の作り方（全部の面・制作物・完成予想図で同じ形にする）

指示文は、1つの関数（案: `buildDesignPrompt(kit, target)`）だけで作る。面も、制作物も、完成予想図も、この関数を通す。次の6つのブロックを、この順に並べる。

1. 役割: 何の面か、仕上がりのサイズ（mm）と縦横比、見る距離、役割。
2. ブースの決まり（共通のブロック）: BDK から作る文。全部の面・制作物で、一字も違わない文字列にする（テストで比べる）。中身は、色（役割ごとの 16 進と面積の比率）、絵の調子（フラット）、書体の雰囲気、帯の角度と幅、円の大きさと位置、上と下の無地の帯の高さ。
3. この面の型と配置: 4.7 の型の名前と、帯・円・文字の位置を、面の幅と高さに対する割合で書く（例:「上から 30% までは主色の帯。その中央に見出し」）。
4. 文字: 確定した文字列を、引用符で、一字も変えずに入れる。位置・大きさ・色（帯の色との対比が 4.5 以上になる色）・改行の位置・書体の雰囲気を書く。「この文字以外は、画面に1文字も描かない」と書く。
5. 禁止: 決まりにない色、写真、3D の描写、実在しないロゴ・認証マーク、斜めのアングル、見出し以外の文字、絵文字。
6. 参照画像の使い方: 「添付の見本の、色・帯と円の形・書体の雰囲気をそのまま使う。見本の中の文字や内容は写さない」。見本の画像は、同じ順番で渡す（1枚目が見本、2枚目がロゴ）。

型と配置と安全領域は、面ごとに計算する。縦横比が細長い面（ロールアップなど）は、モデルが作る縦横比で左右が切られるので、文字を置く幅を狭める（6 章）。

## 5. 生成の流れ（そろえるための順番）

1. BDK を確定する（4.2）。確定するまで、画像を作るボタンを押せないようにする。
2. 見本（マスター）を1枚作る。背面壁の中央（ヒーロー）の背景を、BDK の言葉で作る。利用者が確かめて承認する。気に入らなければ、その1枚だけ作り直す。
3. 残りの面と制作物は、承認した見本を参照画像として渡して作る。参照は、見本と、ロゴ（あれば）の2枚。API の参照を、1枚から複数に増やす（`route.ts` の `referencePng` を配列にする。1枚 4MB まで、合計 2 枚）。
4. 見本は、直列で作る。派生は並列でよい。
5. 面の画像は、面の実寸の縦横比に切り出して保存する（サーバーで sharp を使い、中央から切る。6 章）。文字は安全領域の内側にあるので、切り出しで切れない。
6. 検査する。
   - 文字の確認: 視覚モデル（テキストと画像を受け取る Gemini のモデル）に、「この画像に書かれた文字を、そのまま書き出して」と頼み、確定した文字列と比べる（空白と記号をそろえたあとの編集距離が 0 であること。ゆれを許すなら 1 字まで）。一致しなければ、同じ指示で最大2回まで作り直す。
   - 読めるかの確認: 文字の領域（書き出しで分かる位置）の、明るさの比を測り、4.5 に足りなければ作り直す。
   - 色の確認: 画像の主な色を数色取り出し、BDK のパレットとの色の差（CIEDE2000）を測る。外れたら作り直す。
   - 3回作っても通らない面は、「文字を画像に描かない背景」を作り、文字をコードで重ねた版（逃げ道）にして出す。利用者には、「文字は重ねて作りました」と知らせる。
   - 検査用の呼び出しは、画像の生成より、ずっと安い（テキストモデルの呼び出し。1回の目安は 0.1 円前後。実測で確かめる）。
7. 書き出す。面は実寸の縦横比のまま。書類は PDF。動画は 1920×1080。文字入りの完成画像と、コードで文字を重ねた版の2つを持ち、利用者が選べるようにする。

### 5.1 費用の見込み（目安。画像モデルの単価は `imagegen.ts` の表のとおり）

- 1枚の単価は、約 21 円（gemini-3-pro-image、2K。0.134 ドル × 150 円の切り上げ）。
- 見本のボード3案はコードで描くので 0 円。
- サンプルの 6m×6m のブースで、面は 6〜7 面。見本1枚、面 6 枚、制作物 3 枚（チラシ・クリアファイル・ロールアップの派生）で、10 枚前後。約 210 円。文字の確認で作り直しが出ても、最大 2 回まで（最大 630 円ほど）。
- 文字の確認の呼び出しは、画像1枚につき1回。1回の目安は 0.1 円前後（要実測）。
- 面の図形を、すべてコードで描く版（4.6）では、AI の画像は文字入りの見本の1枚だけ、または 0 枚。
- 従量課金の API なので、実際に回す前に「モデル・枚数・見込み額」を出して承認をもらう（全プロジェクト共通の決まり）。この仕様の作業では、画像生成を回していない。

## 6. 立体表示（3D）で、画像を面に切れずに貼る

本番の 3D の問題（2 章の 13〜17 番）を、次の順で直す。

1. 見出しを、3D の上に重ねない。文字は、画像に含まれている（4.4）。3D の `PanelArt` は、画像を貼るだけにする。重ね文字の白固定・`line-clamp`・割合の字の大きさは、画像がある面からなくす。
2. 面の画像は、面の実寸の縦横比（幅 mm : 高さ mm）に、サーバーで切り出して保存する。モデルが作る縦横比は、10 種類（1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9）から、面に最も近いものを選ぶ。差は、中央からの切り出しで合わせる。
3. 切られる量を、先に計算して、指示文に入れる。たとえば、ロールアップ（850×2000mm、比 0.425）は、9:16（比 0.5625）で作ると、左右が各 15% ほど切られる。この面は、「文字は、中央の 68% の幅の中に置く」と指示する。背面壁の中央（6000×2700mm、比 2.22）は、21:9（比 2.33）で作ると、上下が各 2% ほど切られる。上下の安全領域は、端から 8% を守る。
4. 3D 側は、切り出し済みの画像を、面の寸法の枠に、歪まずに貼る（`object-fit: fill` でなく、枠の比と画像の比が同じなので `cover` のままでよい。比がずれたときだけ、`cover` で中央を切る）。
5. 面の位置は、部材の高さいっぱいではなく、床からの高さ（`baseMm`）と高さ（`heightMm`）で置く（2026-10-27 に実装済み）。
6. 画像のない面（作る前）は、仮の絵を出さず、面の名前と大きさだけの枠にする（制作物スタジオと同じ。2026-10-27 の決まり）。簡易表示を残すなら、文字の色は、背景の明るさから、対比が 4.5 以上になる方を選び、文字を切らずに、枠に合わせて縮める。
7. モニターの文字は、`opacity` で出し入れしない。最初のカットの完成画像を、いつも見える状態で出す。
8. 3D・等角図・制作物のプレビューの色は、BDK のパレットだけで塗る。机・モニター・床の固定の色は、紙・暗色・薄い補助色から選ぶ。予算の円など、ブランドと関係のない画面の色は、ツールの画面の色（ドヤAIの青）にし、ブランドの色と混ぜない。

## 7. 待ち画面（遊び心）

実装済みの試作は `src/components/shell/DoyaWorking.tsx`（共通の部品）。

- 絵: ドヤくんが、ローラーで壁の面を塗る。壁は、BDK と同じ形（上 30% の主色の帯、斜めの帯、円）で、ブランドの色で塗られていく。見ている人は、「この形と色で全部の面ができる」と、待ちながら分かる。
- 状態は、作業中・できた・失敗の3つ。作業中は、ローラーを上げ下げする2枚の絵を入れ替え、絵に弾みをつける。できたときは、親指を立てる絵に替わり、星が出る。
- 進み具合が分かるとき（まとめて作る面の画像）は、塗る高さを、終わった面の割合にそろえる。分からないとき（1枚だけ作る）は、塗って戻す動きを繰り返す。
- 一言は、いま何をしている途中かの目安を、3秒ほどで入れ替える。実際にない工程を作らない。「できた枚数 / 全部の枚数」は、数字で出す。
- 失敗の画面は、責めない言葉で、その1枚だけ作り直せるようにする。
- 動きを減らす設定の人には、塗り終わった形で止める。スクリーンリーダーには、「ドヤくんが画像を作っています」を状態として知らせ、途中の一言は読ませない。
- 使う所: 画像を1枚作る確認の画面（`ImageGenModal`）と、面の画像をまとめて作る画面（`BoothStudio`）。ほかのツール（バナー・広告画像・記事など）の待ち画面にも、`title`・`steps`・`colors` を渡すだけで使える。
- 今後: ブラウザのタブのタイトルに完成の印を付ける、裏のタブなら通知する（許可があるときだけ）。1枚の見込み時間を、過去の実測の幅で出す（例: 30〜60 秒）。
- ドヤくんの共通部品（`src/components/ds/kun.tsx` の `DoyaKun`。ブランチ `feat/motion-kun`、UI リニューアルのセッションが作成。2026-10-29 時点で main には未反映）との関係: 絵の置き場所と名前の付け方を `public/character/<ポーズ>-512.webp` にそろえた。`DoyaKun` が main に入ったら、待ち画面の3つの `<img>` を `DoyaKun` に替え、`KunPose` に `paint-a`・`paint-b`・`paint-done` を足す。壁を塗る場面の構成（壁・ローラー・しずく）は、展示会と、色の決まりを持つツール向けの部品として、`DoyaWorking` に残す。
- 絵の作り方は `docs/design/images/working-bear/PROMPTS.md`（Codex の内蔵の画像生成。ChatGPT の定額の枠で、従量課金の API は使っていない）。

## 8. 実装の順番（段）

| 段 | 内容 | 受け入れ条件 |
|---|---|---|
| S1 | `design-kit.ts`（型・色の規則・コントラストの確認）と、ページからの抽出（theme-color・CSS の変数・ロゴの主な色）。AI は色を作らない | 色の規則の単体テスト（黒白の主色・薄い主色・コントラスト）。テストは `test:tenjikai` に足す |
| S2 | BDK を決める画面（3案の見本ボードをコードで描き、選んで直して確定） | 375px と 1280px で、確定するまで画像のボタンが押せない |
| S3 | 面・制作物・完成予想図の指示文に、BDK の言葉を同じ形で入れる。`visual` の食い違いを直す | 全部の指示文に、同じ BDK のブロックが入るテスト（`design-unify.test.ts` を広げる） |
| S4 | 文字入りの完成画像と、文字の自動確認。見出しの文字列を先に確定し、指示文の4つ目のブロックに入れる。ロゴ・QR・長い文・数字は、コードで重ねる（Satori・resvg）。確認に3回通らない面は、コードで文字を重ねた版にする | 文字の確認が、わざと崩した画像を落とすテスト。確定した文字列が、指示文に一字も変わらずに入るテスト |
| S5 | 見本を先に作って承認する流れ。参照画像を複数に（`route.ts`） | 見本がないと派生が作れない。参照 2 枚で動く |
| S5b | 立体表示の直し（6 章）。サーバーで実寸の縦横比に切り出す。重ね文字をやめる。モニターの文字を固定する | 375px と 1280px の 3D 表示で、文字が切れず、読める（スクリーンショットで確かめる）。ロールアップと背面壁の切られる量が、計算と一致する |
| S6 | 色の検査と補正、コントラストの確認 | 決まりの色から外れた画像が、再生成か補正を通る |
| S7 | モニター用の動画（静止画を動かす）。エンドカード | 3〜6 カット。先頭と末尾の背景色が同じ |
| S8 | 待ち画面を、ほかのツールにも広げる（各ツールの担当と調整） | 各ツールで、動きを減らす設定のときに止まる |

S1〜S2 は AI の画像を使わないので、費用がかからない。S3 の前に、実際に画像を作って確かめたいことが2つある。どちらも従量課金なので、承認をもらってから回す。

- 試し A（日本語の文字の正確さ）: 見出し4種類（短い・長い・数字入り・英字入り）×各3回 = 12 枚。
- 試し B（見本から派生する面の統一）: 見本1枚から、背面壁の左右・ロールアップ・チラシ・クリアファイルを作る6枚 ×2回 = 12 枚。
- 合計 24 枚。モデルは gemini-3-pro-image、解像度は 2K、1枚の単価は約 21 円（0.134 ドル × 150 円の切り上げ）で、合計 約 504 円。文字の確認の呼び出し（24 回）は、数円。
- 回す前に、メインへ「モデル・解像度・1枚の単価・枚数・合計の見込み額」を出し、承認をもらう。

## 9. 決めてほしいこと

1. BDK の見本は、3案から選ぶ形でよいか。それとも、自動で1つに決めるか。
2. 画像は、文字も含めた完成品にする方針（4.4）でよいか。長い文・数字・ロゴ・QR だけは、コードで重ねる。文字の確認に通らない面は、コードで文字を重ねた版にする。
3. 面の図形を、すべてコード（SVG）で描くか。AI の画像は見本の1枚だけ、または使わない。ばらつきは 0 になるが、質感は薄くなる。
4. 動画は、静止画を動かす方法でよいか。AI の動画（MiniMax）を使う場合は、従量課金になる。
5. ロゴは、利用者に上げてもらう入り口を作ってよいか。
6. 書体は、無料で埋め込める Noto Sans JP でよいか。有料書体を使いたい会社への対応は、あとで決める。
7. 待ち画面を、ほかのツールにも広げてよいか（広げる場合は、各ツールの担当と調整する）。

## 10. 調べで確かめられていないこと

- 国内で、書体・クリアファイル・名刺・映像の作りの具体例は、ほとんど見つからなかった。
- 検索の要約だけを根拠にした事例がある（海外の 12・14・24・30・31・35・36 番など）。再確認が必要。
- 色の差（CIEDE2000）の合格線は、出典の無い目安。実際の画像で決める。
- Gemini 3 Pro Image が、参照画像を複数渡したときに、どれほど画風をそろえるかは、実際に回して確かめる必要がある（外部の評価では、一貫性は 5 点満点の 2.2 点という例がある）。検査と補正を入れる理由。
- 展示会の会場ごとの、照明・通路・高さの決まりの違いは調べていない。

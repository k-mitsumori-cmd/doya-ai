# 左のメニューの「よく使うツール」（2026-11-12）

- 左のメニューに「よく使うツール」を、アカウントごとに出してほしい。

## 2. いまの状態

- スマホの下のナビは「ホーム・すべて・アカウント」の固定。

## 3. 戦略

狙いは、いつも使う2〜3のツールに、1回押すだけで行けること。並びが動いて迷わせないこと。

1. 「最近」ではなく「よく使う」で選ぶ。開いた回数を日ごとに数え、直近30日の、開いた日数の多い順に並べる（同じ日に何度開いても1日と数える。たまたま1日に何度も開いたツールが上に来ないようにする）。
2. 並びは、動かさない。順位の計算は、その日の最初の表示のときに1回だけ行い、その日のうちは変えない。画面を移っても入れ替わらない。
3. 出すのは最大5つ。開いた日数が2日以上のツールだけを出す。1つも無いとき（初めての人）は、欄を出さず、今のメニューのままにする。
4. 自分で固定できる。ツールの行のピンのボタンで「いつも上に出す」を切り替える。固定したツールは、回数に関係なく上に出す（固定が先、残りの枠に、よく使う順）。固定は最大5つ。
5. アカウントごとに覚える。まず、ブラウザの中にアカウントの id ごとに保存する（DB の変更なし。すぐ出せる）。最初の描画から並べるため、その日の並びを cookie にも書き、サーバーが読む（あとから欄が出て、下が押し下げられるのを防ぐ）。別の端末でも同じ並びにする（サーバーに保存する）のは、次の段。DB のスキーマの変更が要るので、本人の承認のあとに行う。
6. スマホは、下のナビを変えない（10月24日の決定のまま）。「すべて」を開いた引き出しのいちばん上に、同じ「よく使うツール」を出す。
7. ホームにも同じ並びを使える形（関数）にしておく。今回は左のメニューだけ。

## 4. 仕様

- 記録: ログインした人が、ツールの画面（`/banner/...` など）を開いたとき、そのツールの id と日付（JST）を記録する。保存は localStorage の `doya-shell-freq-v1:<アカウントの id>`。中身は `{ days: { [toolId]: string[] /* 日付。直近30日ぶんだけ */ }, pinned: string[], order: { date: string, ids: string[] } }`。個人の情報は入れない（ツールの id と日付だけ）。
- 並び: `order.date` がきょうでなければ、計算し直して `order` に保存する。きょうなら `order.ids` をそのまま使う。固定の切り替えのときだけ、すぐに並びを作り直す（本人の操作なので、動いてよい）。
- cookie: `doya_shell_freq` に、きょうの並び（ツールの id を最大5つ）だけを書く。アカウントを切り替えたときに前の人の並びが出ないよう、アカウントの id の短いハッシュを前に付け、サーバーは一致するときだけ使う。読むときは、英小文字・数字・`-` だけを通す。
- 表示: ホームの下、まとまりの上に「よく使うツール」の欄。行は今の `NavItem` を使う（mirror。今いるページの印は、本来のまとまりの側だけに付ける）。行にホバーまたはフォーカスすると、ピンのボタンを出す。まとまりの中のツールの行にも、同じピンのボタンを出す。メニューを細くしているときは、アイコンだけを並べる。
- 公開していないツール（開発中で、その人に見えないツール）は出さない。今のメニューに出せるツールの一覧と突き合わせる。
- 純粋な計算（日数の数え方、順位、固定の上限、30日より古い記録を捨てる）は `src/lib/shell/frequent.ts` に置き、テストを書く。
- 旗: `SHELL_FREQUENT_TOOLS_ROLLOUT`（off / preview / all。既定 off。preview は `UI_PREVIEW_EMAILS` の人だけ）。off のときは、記録もしないし、欄も出ない（今のまま）。
- 動き: 欄が出る・入れ替わるときは 280ms。`prefers-reduced-motion` では動かさない。

## 5. 確かめること

- 画面を移っても並びが変わらないこと。翌日に変わること（日付を進めたテスト）。

設計の要点 / 2026-11-01

ドヤバディを、部門ごとの5つの製品に分ける

契約と料金（無料とプロ 月9,980円）、ツールの中身と URL は変えません。左上の切り替えで製品を選ぶと、サイドバーとホームがその部門の分だけになります。

  • 製品は5つです。セールス・マーケティング・人事・予実管理・経営管理。
  • おすすめは A案「見せ方だけ分ける」です。旗で三森さんだけに先に出し、すぐ戻せます。
  • 経営管理のホームは、今の経営ホームです。社長と管理者は、ここから全部を見渡せます。
  • DB は課金の表を変えません。足すのは「会社が使う製品」と「メンバーの担当と既定の製品」の2つの表です。

  • 切り替えはサイドバーのいちばん上です。スマホでは、上の帯の製品名を押すと、下からシートで出ます。
  • 製品のホームは /hub/<id> です。経営管理だけは今の /home を使います。
  • ほかの製品のツールも「すべてのツール」と ⌘K から開けます。隠しません。
  • 最初に開く製品: 本人が選んだもの → 管理者が決めたもの → 最後に開いたもの → 社長・管理者は経営管理。
  • ツールの中のメニューは変えません。

3つの案

A案 見せ方だけ分けるおすすめB案 URL も分けるC案 製品ごとに別のサイト
中身切り替えで、サイドバーとホームが変わる。URL は今のまま/sales/sfa のように URL の頭に製品を付けるsales.doya-ai… のように入口と LP を分ける
今のリンクそのまま開ける転送が要る転送とログインの共有が要る
2つの製品に入るツールURL は1つのままURL が2つになるサイトが2つに分かれる
課金・データ変えない変えないログインの作業が要る
作る量小さい中くらい大きい
戻しやすさ旗を off にすれば戻る戻すと URL がまた変わる戻しにくい

A案は HubSpot と同じ形です。HubSpot は Hub を別のサイトにせず、1つの画面のサイドバーの区分として並べ、既定のホームで担当者の入口を変えています。

表のつながり（ER 図の要約）

課金（変えない）

今のままusersplan（料金の判定はここだけ）
今のままuser_service_subscriptionsserviceId ＝ ツールの id
今のままaccount_company_billing・doya_power_*人数の控えとドヤパワー

会社と役割（今のまま）

今のままaccount_companies1人1社。持ち主
今のままaccount_company_membersrole: admin・manager・billing・member・guest
今のままaccount_company_role_settingspolicy（JSON）。担当の外を隠す設定を、あとで足せる

製品（足す）

新account_company_productscompanyId・productId・enabled・sortOrder。行が無い製品は「使う」
作り替えaccount_company_member_productscompanyId・userId・products（担当）・defaultProduct（既定）。本番にまだ無い部署の表を作り替える
コードsrc/lib/products.ts製品とツールの対応。DB には持たない

ツールの id は課金の serviceId と同じです。製品とツールのつなぎ目はコードの表だけなので、課金の表には触りません。

進め方

段1切り替えとホームの骨組み製品の表・旗・左上の切り替え・サイドバー・製品のホームDB は変えない。旗が off なら今のまま
段2設定会社が使う製品・メンバーの担当と既定の製品表を2つ足す。本番への反映は三森さんの OK のあと
段3中身製品ごとの数字・予実の月の表・ドヤくんの例DB は変えない
段4全員に出す三森さんだけ → 全員。初めの1回だけ案内を出す。LP に「プロ1つで5つの製品」DB は変えない
段5（任意）予算の入力・担当の外を隠すサービスの中身を足すので、三森さんが決めたときだけ表を足す

三森さんに決めてほしいこと

  1. A案（見せ方だけ分ける）で進めてよいか。
  2. 製品は、セールス・マーケティング・人事・予実管理・経営管理の5つでよいか。
  3. 見積もりとプロマネを、2つの製品に入れてよいか。
  4. 予算の入力（段5）を作るか。作らない場合、予実管理は「売上と支払いの予定」と「実績」を比べる形になります。
  5. 担当でない製品も、隠さずに「すべてのツール」から開けるままにしてよいか。

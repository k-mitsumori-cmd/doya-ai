# ドヤAI → ドヤバディ：切り替える日の値の一覧と、本人がすること（2026-10-30）

アプリ側（コード）は、すべて旗 `NEXT_PUBLIC_BRAND_RENAME_ROLLOUT` の裏にあります。旗が off の間は、いまの表示のままです。
この文書は「切り替える日に変える値（今の値 → 新しい値）」と、「本人がすること」の一覧です。**ここに書いた値は、実際には変えていません。**

## 1. 旗と日付（Vercel の環境変数。再デプロイが要る）

| 変数 | いまの値 | 切り替える日の値 | メモ |
|---|---|---|---|
| `NEXT_PUBLIC_BRAND_RENAME_ROLLOUT` | 未設定（= off） | `all` | 画面（クライアント）でも読むので、値を変えたら再デプロイする。本番のビルドは約16分 |
| `NEXT_PUBLIC_BRAND_RENAME_DATE` | 未設定（既定 2026-11-01） | 切り替える日（例 `2026-11-01`） | お知らせのページと、アプリ内のお知らせに出る日付。お知らせは、この日から30日間出る |

## 2. メール・通知（コードの外にある値）

| 場所 | いまの値 | 新しい値 | どこで変えるか |
|---|---|---|---|
| `RESEND_FROM_EMAIL`（Vercel の環境変数） | 値は Vercel にあり、コードには無い（コードの既定は `noreply@doya-ai.surisuta.jp`） | 例 `ドヤバディ <noreply@doya-ai.surisuta.jp>` | Vercel の環境変数。アドレスは今のドメインのまま（Resend のドメイン認証は変えなくてよい）。旗が on のときは、コードが送り主の名前の「ドヤAI」を自動で置き換えるが、名前が無い値（アドレスだけ）のときは、この環境変数に名前を足す必要がある |
| ドリップ配信の送り主の名前（DB `SystemSetting` の `fromName`） | 管理画面で設定した値（コードの既定は「ドヤAI」。seed の例は「三森捷暉｜ドヤマーケ」） | 「ドヤバディ」（または「三森捷暉｜ドヤバディ」）。ドヤマーケの名前を使うかは本人が決める | 管理画面 `/admin/drip/settings` |
| ドリップ配信・ようこそメールの本文のひな形（DB・管理画面） | 「ドヤAI」と書いてある所 | 「ドヤバディ」 | 管理画面のメールの編集。コードの中の固定の文は旗で自動 |
| Slack の通知 | 見出しの札「ドヤAI」 | 「ドヤバディ」 | コードの中は旗で自動。Slack の Incoming Webhook アプリの表示名は、Slack の管理画面で変える |
| サポートチャットの返信メール | 件名「【ドヤAI】お問い合わせへのご返信」、署名「ドヤAI 運営」 | 「【ドヤバディ】…」「ドヤバディ 運営」 | コードの中は旗で自動 |

## 3. Stripe（お金に関わる。本人が確認して変える）

| 場所 | いまの値 | 新しい値 | メモ |
|---|---|---|---|
| 商品名（商品カタログ） | Stripe の管理画面で確認（コードには商品名が無い。価格 ID は環境変数 `STRIPE_PRICE_*`） | 「ドヤバディ プロ」など | 価格 ID は変えない（名前だけ変える） |
| 請求書・領収書に出る事業者名・サービス名 | Stripe の管理画面で確認 | 「株式会社スリスタ」＋サービス名「ドヤバディ」 | 設定 → 公開情報 |
| カードの明細に出る名前（statement descriptor） | Stripe の管理画面で確認 | 例 `DOYA BUDDY` | 変えると、カードの明細の表記が変わる。利用者へのお知らせと合わせる |
| 顧客に送る Stripe のメール（領収書など） | 同上 | 同上 | Stripe の「メール」の設定 |

## 4. HubSpot

| 場所 | 変えるもの |
|---|---|
| フォーム | フォームの名前、送信後のメッセージ |
| メールのテンプレート・ワークフロー | 本文と件名の「ドヤAI」 |
| 会社・取引先のプロパティ | 「サービス名」を入れている項目があれば、値の選択肢 |
| GTM のカスタム HTML（HubSpot のトラッキングコード） | サービス名を入れていなければ変更なし |

## 5. 静的ファイル・画像（コミットで変える）

| 場所 | いまの値 | 新しい値 | やり方 |
|---|---|---|---|
| `public/site.webmanifest`（`name`・`short_name`） | 「ドヤAI」 | 「ドヤバディ」 | `node scripts/brand/rename-public.cjs --write`（切り替える日に実行。変える所の一覧は、`--write` 無しで見られる） |
| `public/resources/doya-ai/*.html`（配布資料3本） | 「ドヤAI」 | 「ドヤバディ」 | 同じスクリプトで書き換える |
| OGP 画像（`public/ogp/*`） | 旧ロゴ・旧名が入っている可能性 | 新しいロゴの OGP | `scripts/brand/build-assets.cjs`（ロゴが決まったら実行。ひな形は `docs/design/brand/buddy-assets/`） |
| `public/logo.png`（構造化データのロゴ） | 旧ロゴ | 新しい文字入りロゴ | 同上 |
| メールの見出し画像 | 旧ロゴ | 新しいロゴ | 同上（ひな形あり） |
| ファビコン・アップルのアイコン | クマのマーク（文字なし） | 変えなくてよい（マークは同じ） | ロゴでマークも変える場合だけ |

## 6. 法務（本人の承認と、法務の確認のあと）

利用規約・プライバシーポリシー・特定商取引法に基づく表記は、旗では変わりません（置き換えの対象外）。書き換え案は `docs/design/brand/TERMS-RENAME-2026-10-30.md` と `.diff` を見てください。

## 7. 本人がする作業（コードの外）

1. ロゴを1つ選ぶ（案A・B・C、統括の画像案、クマのアイコンだけの8パターン）。
2. 商標・ドメイン・SNS の名前は、取らないと決めた（2026-10-30）。
3. 切り替える日を決める。日付を `NEXT_PUBLIC_BRAND_RENAME_DATE` に入れる。
4. 利用規約などの文面を、法務に確認してもらい、公開する。
5. Vercel に `NEXT_PUBLIC_BRAND_RENAME_ROLLOUT=all` と日付を入れ、再デプロイする。
6. Stripe・HubSpot・Resend・ドリップ配信の送り主の名前を、上の表のとおりに変える。
7. 変えたあと、Search Console で、トップとお知らせのページの再登録を申し込み、サイトマップを送り直す。
8. YouTube のチャンネル名・SNS のプロフィール・Google ビジネスプロフィール・紹介記事・プレスリリースの表記を変える（Obsidian の一覧の 6・7）。
9. ドヤマーケ（メディア）で、お知らせの記事を1本出す。

# Stripe Webhook 受信履歴・重複排除

## 目的

署名検証を通った通知のID・種類・処理状態・試行回数をDBに残す。Stripeが同じ通知を再送したとき、完了済みの請求処理を重ねて実行しない。処理中の重複通知には503を返し、最初の処理が失敗・中断した場合は再送で取得し直せるようにする。

## 検証と適用

- 専用PostgreSQL 17で `migration.sql` の初回適用・再適用を確認。
- Prisma経由で初回取得、同時の重複拒否、失敗後の再取得、完了後の重複抑止を確認。
- 単体回帰テストでは古い処理トークンによる完了を拒否し、DB書き込み失敗時に成功応答しないことを確認。
- 本番Vercelの非プーリング接続先と手元の `POSTGRES_URL_NON_POOLING` の接続先を照合。本番DBで対象テーブルが存在しないことを読み取りで確認後、追加DDLのみを適用。
- 適用後の読み取りで9列、主キー、2索引、行数0を確認。既存テーブルの変更・データ補完は行っていない。
- コード: `8334d94c`。GitHub CI `36744411657` は回帰テスト・型チェック・Lint成功。Vercel本番デプロイ `dpl_FBGmvaHVfjzHh5drFjoq5MdLvXmV` はReadyで本番ドメインに割当済み。
- 公開ヘルスチェックはHTTP 200・DB connected。署名付きの無害な独自イベント `evt_codex_receipt_probe_1790786240179` を本番Webhookへ送信し、初回200・同一ID再送200・不正署名400を確認。DB行は `processed`、処理試行回数1。実際のStripe配送からの往復試験ではない。

## 復旧

コードを先に前版へ戻せば新テーブルを参照しなくなる。テーブルの削除は不要で、受信履歴を保持したまま復旧できる。署名シークレットや通知本文は記録しない。

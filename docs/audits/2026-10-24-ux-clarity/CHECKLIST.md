# 分かりやすさと機能のチェックリスト（2026-10-24）

ドヤAIの全ツールを、同じ物差しで点検するための一覧です。
項目には ID を付けました。点検の結果は AUDIT.md に、ID ごとに書きます。

## 判定の決まり

| 判定 | 意味 |
|------|------|
| OK | 「何を見れば OK か」を満たしている |
| 要改善 | 使えるが、迷う・見落とす・手間が多い |
| NG | 利用者が先に進めない、または誤った結果になる |
| コードでは判断できない | ブラウザで画面を見ないと決められない。確かめる手順を書く |

## きっかけになった声

- 左のメニューの下の部分が、ツールを開くたびに変わるので分かりにくい（2026-10-24）。
- ドヤ展示会の画面がいちばん分かりやすい。ほかのツールもこれを見本に直したい（2026-10-24）。
- アイコンや絵が白い箱で浮いて見えるのは嫌だ。全面の読み込みや青いフラッシュを出さない。日本語で1文字だけの行を出さない。UIに絵文字を使わない（以前の指摘）。

## FRM 枠（上の帯・左のメニュー・下のタブ）

| ID | 確かめること | 何を見れば OK か |
|----|------|------|
| FRM-01 | 左のメニューの下の部分が、ツールを移っても同じ | 左下は「登録会社・ドヤパワー・アカウント」だけで、ツールごとの数字やボタンが入れ替わらない。`AppShell.tsx` の `ShellUsageArea` が左下に無い |
| FRM-02 | 左のメニューの並びが、押すたびに変わらない | 「最近使ったツール」のように、押した順で並びが動く区画が無い。または動く区画が、決まった区画と見た目ではっきり分かれている |
| FRM-03 | スマホの下のタブが、押すたびに変わらない | 下のタブの中身が決まっている（ホーム・すべて・アカウントなど）。最近使ったツールで入れ替わる枠が無い |
| FRM-04 | ツールの中のタブ（ToolFrame の nav）の位置と名前が、画面を移っても同じ | ツールの全画面で同じ `nav` 配列を渡している。画面ごとに別のタブ列や独自サイドバーを出していない |
| FRM-05 | 枠の中に出るべき画面が、枠の外に出ない | ログイン後の入口・料金・はじめにの画面も枠の中に出る（`registry.ts` の `shouldShowShell`）。押したら上の帯が消える画面が無い |
| FRM-06 | ツールの見出しの帯に、ツールごとの情報（残り・プラン）がまとまっている | 残りの回数やプランが、左下ではなく見出しの帯（ToolFrame）に出ている |
| FRM-07 | 枠が二重にならない | ツールの古い独自サイドバーや独自ヘッダーが、共通の枠の中にもう一度出ない |
| FRM-08 | パンくずが「経営ホーム / ツール名」で、ツール名がメニューと同じ | `findShellTool(id).name` と見出し・メニューの名前が同じ |

## NXT 次にやることが1つに見える

| ID | 確かめること | 何を見れば OK か |

## TRM 用語がそろっている

| ID | 確かめること | 何を見れば OK か |

| TRM-05 | 「初月無料」を直書きしない | `TrialCallout.tsx` の部品を通している（課金仕様） |

## STA 空状態・読み込み・失敗・完了

| ID | 確かめること | 何を見れば OK か |
|----|------|------|
| STA-01 | 空の一覧に、絵と一文と作るボタンがある | 共通の `EmptyState`（絵・見出し・説明・ボタン1つ）を使う |
| STA-02 | 全面の読み込みを出さない | 枠と見出しを残し、中身だけ骨組み（`ShellLoading`）か細い線。画面全体の白や青のくるくるを出さない |
| STA-03 | 生成の待ち時間に、進み具合が見える | 手順の一覧・割合・今の段が出る（展示会の `Generating.tsx` の型） |
| STA-04 | 失敗の文が日本語で、直し方とやり直しのボタンがある | 「時間をおいて、もう一度お試しください」と「もう一度」ボタン。途中まで済んだ分は残す |
| STA-05 | 失敗を黙って捨てない | `catch {}` で何も出さない箇所が、主な操作に無い |
| STA-06 | 完了が分かる | 保存・作成・削除のあとに、トーストか画面の変化で「済んだ」が分かる |
| STA-07 | 二度押しで二重に作られない | 実行中はボタンを押せない（`disabled`） |

## FN 機能

| ID | 確かめること | 何を見れば OK か |
|----|------|------|
| FN-01 | 主な操作が最後まで通る | 画面 → API → DB → 画面の戻りまで、呼び先の API が存在し、返す形と画面の読む形が合う |
| FN-02 | 作ったものが保存され、再読み込みしても残る | 結果を DB に保存している。画面の状態だけに持っていない |
| FN-03 | 削除に確認があり、削除後に一覧が正しく変わる | 確認のダイアログ。削除後に一覧を読み直す |
| FN-04 | エラーのあとに、入力が消えずに戻れる | 失敗しても入力欄の中身が残る |
| FN-05 | 権限の確認がサーバー側にある | API が `getServerSession` と所有者（userId・組織）で絞る。`[id]` 系は id と持ち主の二重条件 |
| FN-06 | 課金の上限をサーバー側で数える | 生成の API が上限を数え、超えたら 429 などで止める。画面の数字だけで止めていない |
| FN-07 | 画面が読む API の形と、API の返す形が合う | フィールド名の食い違い・存在しない API の呼び出しが無い |
| FN-08 | URL を直接開いても、その画面が出る | 途中の画面の URL を開いたとき、入力の画面に戻されない・空にならない |

| ID | 確かめること | 何を見れば OK か |

# ドヤ展示会は、なぜ分かりやすいか（2026-10-24）

ユーザーは「ドヤ展示会の画面がいちばん分かりやすい」と話しています。
この文書では、その理由をコードの行で示します。
そのうえで、ほかのツールに当てはめられる「型」（T1〜T8）としてまとめます。

対象のファイル:

- 画面: `src/app/(shell)/tenjikai/layout.tsx`、`src/components/tenjikai/*.tsx`
- 計算とナビ: `src/lib/tenjikai/engine.ts`、`src/lib/tenjikai/nav.ts`
- API: `src/app/api/tenjikai/generate/route.ts`、`src/app/api/tenjikai/image/route.ts`

「ガチャ」について: コードを `ガチャ|gacha|くじ|抽選` で探しましたが、展示会の中には見つかりませんでした。
ユーザーの言う楽しさに近いのは、「3つの案から選ぶ」「画像を作り直す」「作った面が3Dに貼られていく」の3つです。
この文書では、この3つを楽しさの仕掛けとして扱います（T5）。

## 1. 1画面で、次にやることが1つに決まっている

ブース設計の画面では、本文の最初に「次にやること」の帯があります。
帯には、今の状態を表す一文と、塗りつぶしのボタンが1つだけあります。

- 一文は状態で3通りに変わります（`BoothStudio.tsx:183`）。
  - まだのとき:「次は、面の画像を作ります（3/8面が完成）。」
  - 作っている間:「面の画像を作っています（2/5面）。できた面から3Dに貼られます。」
  - 終わったとき:「すべての面に画像を貼りました。書き出して、印刷会社に渡せます。」
- ボタンも状態で入れ替わります（`BoothStudio.tsx:187-198`）。終わる前は「面の画像をまとめて作る（5面）」、終わったら「書き出す」です。
- 条件を入れ終わると、結果の一覧ではなくブース設計の画面へ自動で移ります（`TenjikaiApp.tsx:85-91`）。最初に何を見ればよいかを、ツールの側が決めています。

型にすると、次のとおりです。

> **T1 次にやること帯**: 本文の最初に、白い帯を1本置く。中身は「次は○○します（n/m 完了）」の一文と、主ボタン1つ。状態（未着手・実行中・完了）で文とボタンを入れ替える。

気を付ける点: ブース設計の画面では、下の「グラフィック割付」にも面ごとの塗りつぶしのボタンがあります（`GraphicPlanner.tsx:144`）。
そのため、厳密には主ボタンが2種類見えます。ほかのツールに広げるときは、帯の外のボタンを枠線だけにします。

## 2. 進み具合の見せ方

進み具合は、3か所で見せています。

1. **手順の札**（`BoothStudio.tsx:65-84`）
   「条件を入れる → 3Dで確かめる → 面の画像を作る → 書き出す」の4段です。
   済んだ段にはチェック、今の段には青い枠を付けます。`aria-current="step"` も付いています。
2. **数の表示**（`BoothStudio.tsx:183`、`:236`）
   「面の画像 3/8」のように、分母と分子を見せます。
3. **生成中の一覧**（`Generating.tsx:14-35`、`:84-112`）
   「サイトを読み込み」「ブースを3案設計」など10の段を並べます。済んだ段にチェック、今の段に回る印を付けます。円のゲージと割合（%）も出します。
   段の文に、利用者の入力（ドメイン名・会場名・寸法・来場者数）を埋め込んでいます（`Generating.tsx:15-21`）。そのため、自分の条件で作業が進んでいると分かります。

> **T2 手順の札**: 3〜5段の手順を横に並べ、済み・今・まだを色と印で分ける。今の段に `aria-current="step"` を付ける。
>
> **T3 生成中の手順一覧**: 5秒以上かかる生成では、段の一覧と割合を出す。段の文に利用者の入力を入れる。API と表示の両方が終わってから次の画面へ移る（`TenjikaiApp.tsx:84-91`）。

気を付ける点: 段は 520ms ごとに進む決まった表示で、API の実際の進み具合ではありません（`Generating.tsx:10`、`:33`）。
API が遅いときは、100% のまま待つことになります。ほかのツールでは、最後の段を「仕上げています」にして、そこで待たせます。

## 3. キャラクター（ドヤくん）の使い方

キャラクターの絵は、3つの場面で出ます。

| 場面 | ファイルと行 | 絵 |
|------|------|------|
| 入口（条件の入力） | `Wizard.tsx:62-64` | `/ui-renewal/mascots/tenjikai.webp`（ブースの模型と名刺を持つシロクマ） |
| 作業中 | `Generating.tsx:83` | `/tenjikai/working.webp` |
| 結果の見本 | `BoothStudio.tsx:299-304` | `/tenjikai/booth-sample.webp`（まだ画像が無いときだけ） |

- 絵は背景が透明の webp で、白い箱や影を付けていません（直近のコミット 80946590 で白い背景を抜きました）。
- 作業中の絵は `alt=""` で、読み上げでは飛ばします（`Generating.tsx:83`）。入口の絵には、何の絵かの説明があります。
- キャラクターは説明の主役ではありません。文と入力欄の横に置き、話させていません。

> **T4 キャラクターの出し方**: 入口・作業中・空状態の3つの場面で、ツール専用のキャラクターの絵を出す。背景は透明にし、絵の中に文字を入れない。セリフの吹き出しは付けない。

## 4. 楽しさの仕掛け

- **3つの案から選ぶ**（`BoothStudio.tsx:213-221`）
  1回の入力で、案A・B・Cの3つを作ります。選ぶと、青い札がばねの動きで移ります（`layoutId="variantTab"`）。
  出展の目的から、最初に選ぶ案を決めています（`TenjikaiApp.tsx:69`）。
- **作り直す**（`GraphicPlanner.tsx:145`、`CreativeStudio.tsx:211`）
  画像があるときは、ボタンの文が「作り直す」に変わります。何度でも引き直せます。
- **作った面が3Dに貼られていく**（`BoothStudio.tsx:149-168`）
  まとめて作ると、1面できるたびに3Dの壁面に貼られます。結果が少しずつ組み上がるのが見えます。
- **回せる3D**（`Booth3D.tsx`）と、数字が増えていく表示（`ui.tsx:24-32` の `CountUp`）。

> **T5 案を選び直せる**: 1回の生成で2〜3の案を見せ、札で切り替える。気に入らなければ「作り直す」で引き直せる。結果が少しずつ組み上がる様子を見せる。

## 5. 言葉の選び方

- 見出しは「URLひとつで、展示会の準備をまるごと。」（`Wizard.tsx:44-50`）。短い3行に分け、各行に `whitespace-nowrap` を付けて、1文字の行が出ないようにしています。
- 動詞で終わるボタン:「展示会の準備を一括作成」「面の画像をまとめて作る」「作りはじめる」「書き出す」「割付表と画像を保存」。
- 小間の位置の札は、名前と「（何面開放）」を別の行に分けています。1文字だけの行（「放）」）を出さないためです（`Wizard.tsx:154-158`）。
- 原価・モデル・解像度は見せず、「きょう作れる残り：n枚（1日m枚まで）」だけを見せます（`ImageGenModal.tsx:4`、`useImageGen.ts:57-60`）。
- エラーにステータスコードを出しません（`useImageGen.ts:44-52`）。

> **言葉の決まり**: ボタンは「○○を作る／書き出す」の動詞で終える。内部の言葉（モデル名・原価・HTTP のコード）は出さない。残りは「きょう作れる残り」で言う。

## 6. 空状態・完了・失敗の見せ方

- 空・失敗・権限なしは、1つの部品 `EmptyState` にまとめています（`EmptyState.tsx:22-57`）。絵・見出し・説明・ボタン1つの形です。失敗のときは `role="alert"`、それ以外は `role="status"` です。
- まとめて作る途中で失敗したときは、済んだ分を残します。「3面ぶんは3Dに貼りました。残りの面から作り直せます。」と書き、「残りの面を作る」ボタンを出します（`BoothStudio.tsx:200-211`）。
- 失敗の種類でボタンを変えます。通信の失敗は「もう一度」、未ログインは「ログインする」、準備中はボタン無しです（`ImageGenModal.tsx:66-82`）。
- AI での作成に失敗しても、画面は止めません。下書きを出し、その旨を黄色の帯で伝えます（`engine.ts:499-513`、`TenjikaiApp.tsx:131-135`）。
- 完了は、帯の文とボタンが「書き出す」に変わることで伝えます（`BoothStudio.tsx:183`、`:187-190`）。

> **T7 失敗の箱**: 空・失敗・権限なしは `EmptyState` 1つで出す。途中まで済んだ分は残し、「残りを作る」で続きから再開できるようにする。AI が失敗しても、下書きと説明の帯で画面を止めない。

## 7. 入力の量

- 入力は1画面に収まります（`Wizard.tsx:67-205`）。URL・展示会名・会期・日数・会場・小間・位置・予算・目的・人数の10項目です。
- すべての欄に、最初から例が入っています。右上に「サンプル入力済み」の札を出しています（`Wizard.tsx:76`、`TenjikaiApp.tsx:41`）。そのため、何も入れずにボタンを押しても結果が見られます。
- 文字を打つ欄は3つ（URL・展示会名・会期）だけです。ほかはマス・札・スライダー・選択で選びます（`Wizard.tsx:106-194`）。
- 入力の途中で、結果の目安を出します。「想定来場 3,600 人（2日間）をもとに…」（`Wizard.tsx:196-199`）。
- 読み込みが終わるまでは、送信ボタンを押せません（`Wizard.tsx:33-35`、`:200`）。

> **T6 サンプル入力済みの短いフォーム**: 1画面に収め、全欄に例を入れて「サンプル入力済み」と示す。文字の欄は3つまでにし、残りは選ぶ形にする。入力中に結果の目安を出す。

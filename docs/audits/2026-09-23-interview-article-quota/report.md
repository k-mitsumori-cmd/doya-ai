# ドヤインタビューの記事生成枠の修正

## 確定した仕様

- 1日の枠は JST 0:00 に切り替える。
- 記事の初回生成と再生成をそれぞれ1回と数える。プロジェクト作成は記事生成枠に含めない。
- ゲスト2回、FREE 5回、LIGHT 10回、PRO 30回、ENTERPRISE 100回。
- AI生成または記事保存の失敗時は予約した枠を戻す。保存済みの記事は、後続の補助処理が失敗しても1回と数える。
- 上限時は生成APIから `ARTICLE_LIMIT` と料金ページへの導線を返し、画面に表示する。

## 実装と検証

- `SystemSetting` の一意キーでユーザーまたはゲスト単位のカウンターを原子的に更新し、同時リクエストによる上限超過を防ぐ。
- データベースが確認できない場合は AI 呼び出し前に止める。
- 記事が空の場合は保存せず枠を戻す。
- 画面から生成をキャンセルした場合はAI接続を中断し、保存前なら枠を戻す。
- 生成画面を再読み込みした場合は自動で再生成せず、明示的な開始ボタンを表示する。開始ボタンの連打や React の効果再実行も同時送信しない。
- 同一プロジェクトのドラフト版番号採番、ドラフト保存、プロジェクト・レシピ更新は短いトランザクションで確定する。更新失敗時にはドラフトを残さず枠を戻す。
- 回帰テストで、上限時にAIを呼ばないこと、AI失敗時に枠を戻すこと、記事保存成功時に枠を消費することを確認した。
- 関連更新失敗時のロールバックと枠返却、続く生成で版番号が重複しないことを確認した。
- 記事確定後に利用ログ・通知が失敗しても生成成功を利用者へ返すことを確認した。
- AI応答待ちのキャンセルで、記事を保存せず枠を戻すことを確認した。
- AI応答の最終行に改行がなくても取り込み、複数の本文パートを欠落させないことを確認した。
- `npm run build`、`npx tsc --noEmit --pretty false`、対象ファイルの ESLint を確認した。ESLint は既存の画像・フォント警告のみ。

## 残る制約

- ゲスト枠は既存のゲストCookieを識別子とするため、Cookieを消すことで別ゲストとして扱われる。この制限を不正利用対策の代わりにはできない。
- プロセスが枠予約後に強制終了すると、失敗分の返却処理を実行できない。その場合は次の JST 0:00 に枠が回復する。

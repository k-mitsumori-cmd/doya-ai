# 管理画面のバナー残枠の整合性（2026-09-23）

## 確認した不一致

- 生成APIは `UserServiceSubscription.monthlyUsage` をJST当月として判定し、FREE 15枚、LIGHT 50枚、PRO 150枚、ENTERPRISE 1000枚を上限にする。
- 管理者のユーザー一覧・詳細は旧定義の9／50／500枚と `dailyUsage` を使って「本日の残り」を表示していた。リセットボタンも `dailyUsage` を0にしており、バナー生成の月間上限には効かなかった。
- CSVも「バナーAI今日の使用数」として `dailyUsage` を書き出していた。

## 修正

- 管理APIから生成APIと同じ料金定義とJST月替わり判定で計算した `bannerQuota` を返し、一覧・詳細画面で今月の使用・残りを表示する。
- バナーのリセット操作は `monthlyUsage` を対象にする。日次・月次で共有する `lastUsageReset` を更新するときは、他方の古いカウンターを0に均してから保存する。
- CSVは「バナーAI今月の使用枚数」とし、月替わり後の古い値を0として出力する。JSONには月間枠の集計値を追加する。
- 再取得した管理APIの結果で編集中のユーザー表示も更新し、操作直後に古い残枠へ戻らないようにした。

## 検証と限界

FREE／LIGHT／PRO／ENTERPRISE、月替わり、上限無効化の単体回帰テスト、および管理APIの月間リセット・共有タイムスタンプの回帰テストを追加した。`npm run build`（全セキュリティ回帰テスト、型チェック、Next.js本番ビルド）を通過した。管理者認証での本番操作や実ユーザーデータの変更は行っていない。

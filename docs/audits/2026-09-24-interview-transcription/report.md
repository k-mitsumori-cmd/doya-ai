# ドヤインタビュー文字起こし上限の設計監査

## 確認した問題

- 料金定義はゲスト合計5分、ログインFREE月30分、LIGHT月60分、PRO月150分、ENTERPRISE月1000分と案内する。一方、`POST /api/interview/materials/[id]/transcribe` と `GET /api/interview/materials/[id]/transcribe-stream` はゲストの完了済み秒数だけを確認し、ログイン利用者の月間上限を確認しない。
- ゲストも「既に使用した秒数が上限以上か」だけを確認するため、残り1秒でも長尺ファイルを開始できる。同時実行や同じ素材の再実行も加味されず、処理費用と利用枠が増え得る。
- `/api/interview/usage` は素材の作成日を基準に月間使用量を出す。前月にアップロードした素材を今月文字起こしすると当月分から漏れる。またサーバーのローカル月初を使うため、日本時間の月初とずれる。
- 完了済み素材や文字起こし記録を削除すると、現在の集計では使用済み分数も減る。月間上限に必要な利用履歴は素材の保存状態と独立して保持する必要がある。
- 「1回最大約3時間」と「FREE月30分」などの併記では、残り枠を超える1本の扱いが不明瞭。開始前に厳密に止めるには、プロバイダーへ送る前に音声の実時間を信頼できる方法で検証する必要がある。AssemblyAIの[公式資料](https://www.assemblyai.com/docs/faq/what-is-the-minimum-audio-duration-that-the-api-can-transcribe)も事前のメディア長チェックを案内している。

## 修正条件

- 両API入口で同じサーバー側の利用枠を使い、再接続は二重消費しない。
- 上限判定と新規ジョブ開始を並行リクエストでも原子的に行う。失敗したジョブは予約枠を返し、完了した秒数は素材・プロジェクトの削除後も当月の利用量として残す。
- 日本時間の月初で集計し、画面表示とサーバー判定に同じ数値を使う。対象ファイルの長さを検証できない場合は、上限を守れたと偽らず安全なエラーとして扱う。
- 残り時間を超える1本は、開始前に止める方針で実装・検証を進める。現時点で本番上限が実装済みとは扱わない。

## 先行補修

- 使用量APIは素材の完了時に更新される `updatedAt` を使い、日本時間の月初（UTCでは前月末15:00）から集計するよう変更した。これで「前月アップロード・今月完了」の数え落としと月初9時間のずれを解消する。
- この集計は素材を削除すると減るため、請求・上限判定の永続的な台帳としては使わない。両文字起こしAPIの月間上限もまだ未実装。

## 音声長の検証準備

- ブラウザーが申告した秒数を信用せず、Storage内の実ファイルをサーバーから分割取得してMediaInfoで解析する関数を用意した。署名付きURLのホスト、HTTP 206とContent-Range、取得量上限32MiB・64回、1回の取得上限1MiBを検証し、確認できなければエラーにする。
- 合成WAVと既存のMP4・WebMでMediaInfoの解析をローカル確認し、分割取得の不正応答・別ホスト・短い応答を回帰テストで拒否する。
- 2026-09-24 01:48 JST頃、非公開の本番Storageに合成WAVを一時的に置き、署名付きURLへの範囲リクエストがHTTP 206、正確なContent-Range、256バイトを返すことを確認した。検証用ファイルはStorage APIで削除し、一覧から消えたことを確認した。利用者のファイルは読んでいない。
- この関数は両開始APIに機能フラグ付きで接続した。予約台帳は並列開始時の枠を原子的に確保し、成功時に確定、失敗時に返す。枠超過時に外部AIを呼ばないことは両入口の回帰テストで確認した。
- ただし `INTERVIEW_TRANSCRIPTION_QUOTA_ENABLED` は本番で未設定。POST経路のワーカー停止・外部ジョブの結果不明時に予約を安全に回収または再開する設計、および全対応形式での本番動作は未検証。現時点で月間上限を守れるとは案内しない。
- MediaInfo の通常バンドルは Next.js ビルドで WASM を解決できず失敗したため、サーバー外部パッケージと両APIのファイル追跡を設定した。その後の Next.js ビルドは成功し、両APIのトレースに `MediaInfoModule.wasm` が含まれることを確認した。

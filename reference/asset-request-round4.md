## 0. 結論: ロゴが「無い」サービスは0件。ただし13点が規格外

公開17サービス全てに `public/<id>/logo.png` が存在する。絵柄も全点が白クマ＋太アウトラインの
統一されたアートディレクションで、描き直しは不要。

**問題は形式だけ**で、規格を満たしているのは第1弾で制作した新4件のみ。

### なぜ直す必要があるか

1. **並びで浮く。** `ToolSwitcherMenu` は高さ80pxで `object-contain` 表示するため、
   2016×864 のロゴは幅187pxで描画されるのに対し、2048×2048 の正方形は幅80pxにしかならない。
   同じメニュー内で banner / seo / interview / persona の4件だけが小さく見える
2. **重い。** 最大3.8MB。`next/image` が配信時に最適化するとはいえ、原本が重いと
   ビルド時の変換コストが上がり、初回変換のレスポンスも遅れる
3. **タグラインの焼き込みが不統一。** banner のロゴには「バナー制作を、AIでもっとカンタンに。」
   が画像内に入っているが、横長系の他サービスには無い

## 1. 依頼 R4-A: 既存13点の再書き出し

| 項目 | 仕様 |
|---|---|
| 対象 | banner / seo / interview / persona / kintai / hr / doyalist / doyaslide / cunning / promane / sfa / shodan / aio |
| 寸法 | **2016 × 864** に統一 |
| 形式 | PNG 背景透過 ＋ WebP の2点セット |
| 容量 | **PNG 150KB以下**（新4件は64〜84KBで収まっている） |
| 配置 | `public/<serviceId>/logo.png` ＋ `logo.webp`（上書き） |
| 絵柄 | **描き直さない。**既存の絵をそのまま使う |
| 作業内容 | ① 正方形5件は構図を横長へ再構成 ② 全13件を減色・最適化して容量を落とす ③ WebP を書き出す |

### 正方形5件の横長化について

`banner / seo / interview / persona` は要素が縦に積まれた正方形構図のため、単純な
リサイズでは横長にならない。以下のいずれかで対応する。

- **推奨**: 既存ロゴを参照画像として `generateImageWithFallback()` に渡し、
  同一の白クマ・同一の配色・同一の太アウトラインを保ったまま 2016×864 の構図へ再構成する
  （第1弾で新4件のアイコンを作ったときと同じ手順）
- 代替: 主要素（白クマ＋ロゴタイプ）だけを切り出し、横長の枠に組み直す

`kintai`（1254×480）は比率が近いので、拡大とパディング調整で 2016×864 に収まる。

### タグラインの扱い

banner のロゴ内にある「バナー制作を、AIでもっとカンタンに。」は、横長化の際に**外す**。
理由は次の2点。

- 他16サービスのロゴにタグラインが無く、統一されていない
- ロゴは小サイズでも使う。80px高では読めず、潰れたノイズにしかならない
- 文言が必要ならHTML側で出す（画像に日本語を焼き込まない原則にも沿う）

## 3. 共通規約

- 絵文字を使わない
- 画像に日本語テキストを焼き込まない（既存ロゴタイプは例外。再書き出し時に字形が崩れていないか必ず目視）
- 基調は `#0066ff`。既存ロゴの配色は変えない
- 生成は `generateImageWithFallback()` 経由（直接API呼び出しは禁止）
- 参照画像を渡す場合、**透過が要るので `background: 'transparent'` を明示的に渡す**
  （既定は不透過。2026-08-20の変更）
- gpt-image-2 は 16の倍数・アスペクト比3:1以内・最大3840px。2016×864 は約2.33:1で範囲内

# ドヤ見積もりAI（quote）— 要件定義書

> ステータス: **実装済み / 本番稼働中**（2026-08-08）
> 本番: https://doya-ai.surisuta.jp/quote
> 作成日: 2026-08-06
> 想定 serviceId: `quote` ／ パス: `/quote`
> ⚠️ serviceId は要確認。`mitsumori`（見積の素直な romanization）も候補だが、運営者の姓（三森）と衝突して
> ログ・URL・分析上まぎらわしいため、本書は `quote` を仮置きする。
> 本書は「何を作るか」の正本。実装着手時はまず本書を読み、変更があれば本書を先に更新すること。

---

## 1. 概要

**サービスURLを入れるだけで、その商材に合った見積もり品目と相場価格が並び、自分用に調整して、その場でPDFの見積書にできる**ツール。

商談で「では見積もりは後日お送りします」と言った瞬間、熱は冷める。
その場で出せれば商談はそのまま前に進む。**「見積もりを持ち帰らせない」**のが本サービスの存在理由。

| 項目 | 内容 |
|---|---|
| サービスID | `quote` |
| パス | `/quote` |
| カテゴリ | sales / document |
| ステータス（初期） | `coming_soon` → Phase 1 完了後に `beta` |
| アイコン | `request_quote`（Material Symbols） |
| カラー | ブランド `#0066ff` |

### 解く課題

| 課題 | 現状 | 本サービスでの解決 |
|---|---|---|
| 見積もりが商談の場で出せない | 持ち帰って作成 → 送付まで数日 → 熱が冷める | URL入力から数分で見積書PDFまで到達 |
| 価格の付け方が分からない | 相場が分からず、安すぎ/高すぎで失注 | 品目ごとに相場レンジ（下限・中央・上限）を**出典付き**で提示 |
| 見積書の作成が毎回手作業 | Excelの使い回し、計算ミス・税率ミス | 明細・消費税・合計を自動計算、テンプレートから即生成 |
| 担当者ごとに見積もりがバラバラ | 単価が人によって違う | 自社の単価マスタ（レートカード）に集約 |

### やらないこと（スコープ外・MVP）

- 請求書・発注書・納品書の発行（見積書に限定。将来検討）
- 会計ソフト連携（freee / マネーフォワード等）
- 電子契約・電子署名（角印の画像貼付までは対応、法的な電子署名は対象外）
- 原価計算・粗利管理

## 2. 体験フロー

1. **商材URLを入力** — 自社サービスのURLを入れる（資料アップロードも可）
2. **AIが商材を理解** — 何を売っているか / 提供形態（SaaS・受託・コンサル・制作）/ 想定顧客規模を抽出
3. **見積もり品目の候補が並ぶ** — 初期費用・月額・オプション・工数など。各品目に**相場レンジと出典**
4. **自分用にカスタマイズ** — 品目の追加/削除、単価の上書き、数量・期間の調整。値引き・特記事項
5. **保存すると自社の単価マスタになる** — 次回からその単価が既定値。担当者間のブレが消える
6. **見積書としてまとめる** — 宛先・件名・有効期限・支払条件・消費税を設定
7. **PDF出力** — その場でダウンロード / メール送付 / 共有リンク
8. **（連携）AI商談の途中から呼べる** — 商談で聴取した規模・予算をそのまま初期値にして生成

## 3. 機能要件

### F1. 商材の取り込みと理解

- **URL取り込み**: 既存 `src/lib/cunning/scraper.ts` / `src/lib/net/safe-fetch.ts`（SSRF対策済み）を再利用。料金ページがあれば優先的に読む
- **ファイル取り込み**: PDF / PPTX / DOCX（サービス資料・既存の見積書）
- **抽出する商材プロフィール**
  - 提供形態（SaaSサブスク / 受託制作 / コンサル / 運用代行 / ライセンス / スポット）
  - 課金軸（月額 / 従量 / 人数 / 制作物単位 / 工数）
  - 想定顧客規模、提供範囲、オプションになりうる要素
- ⚠️ 自社サイトに価格が書いてある場合、**それが最優先の一次情報**。相場より自社の公開価格を優先する

### F2. 見積もり品目の生成と相場の提示（本サービスの中核）

**「バーッと出てくる」の中身は、根拠のある金額でなければ意味がない。** 価格の出所を4層に分け、優先順位を固定する。

| 優先 | 出所 | 内容 | 信頼度 |
|---|---|---|---|
| 1 | **自社の単価マスタ**（レートカード） | 過去に自分で確定させた単価 | 最高 |
| 2 | **自社サイトの公開価格** | 商材URLから抽出した価格表 | 高 |
| 3 | **相場マスタ**（内蔵データ） | 施策・業種別の相場テーブル | 中 |
| 4 | **競合の公開価格** | 公開されている料金ページの収集結果（出典URL付き） | 中〜低 |

> ⚠️ **LLMの内部知識だけで金額を出すことは禁止**。相場は事業判断に直結し、根拠のない数字は実害になる。
> 上記のいずれにも当たらない品目は、金額を空欄にして「要見積」と表示する（勝手に埋めない）。

- **相場マスタの初期データ**: ドヤマーケAIのメディア記事群が既に施策別・規模別の相場表を持っている
  （SEOコンサル 月15〜50万 / 記事制作 1本3〜8万 / サイト制作 30〜500万 / MA導入 15〜60万 等）。
  これは**自社が公開した一次情報**なので、出典付きで初期シードにできる。
- **表示**: 各品目に `下限 / 中央値 / 上限` の3点 ＋ 出典ラベル ＋ 「なぜこの価格帯か」の一文
- **プリセット**: 「松・竹・梅」の3プラン構成を自動生成（商談で選ばせる形にできる）

### F3. カスタマイズと単価マスタ

- 明細の追加・削除・並べ替え、品目名/仕様/数量/単位/単価の編集
- **単価マスタ（レートカード）**: 確定した単価を商材ごとに保存。次回の既定値になる
- **見積テンプレート**: よく使う構成（例:「初期＋月額12ヶ月」「制作一式」）を保存して呼び出す
- 値引き（率 / 額）、端数処理ルール、通貨は日本円のみ（MVP）

### F4. 見積書の生成

日本の商習慣で必要な項目を満たすこと。ここを外すと実務で使えない。

- **ヘッダ**: 見積書番号（自動採番）/ 発行日 / **有効期限**（既定30日）
- **宛先**: 会社名（御中）/ 部署 / 担当者名（様）
- **件名**
- **発行者**: 社名 / 住所 / 電話 / 担当者 / ロゴ / **角印画像**（任意アップロード）
- **明細**: 品目 / 仕様・備考 / 数量 / 単位 / 単価 / 金額
- **金額**: 小計 → 値引き → **消費税（税率別に 10% / 8% を分けて表示）** → 合計
- **条件**: 支払条件 / 納期 / 備考 / 特記事項
- **インボイス登録番号**（T+13桁）— 見積書は適格請求書ではないが記載が一般的。設定で表示ON/OFF
- ⚠️ **消費税の計算と税率区分は実害が出る箇所**。丸め規則を固定し、テストデータで検算すること

### F5. PDF出力

- **方式: puppeteer-core + @sparticuz/chromium で HTML → PDF**
  - 既存 `src/lib/adsim/pdf-generator.ts` が同方式で稼働中。**日本語が文字化けしない**（ヘッドレスChromeがNoto CJK内蔵）ため、フォント埋め込みの苦労が要らない
  - jsPDF 単体は日本語フォントの埋め込みが必要になるため、文書PDFには使わない（画像PDFの `doyaslide/export` とは用途が違う）
- ⚠️ **Vercel Functions のレスポンス本文上限（約4.5MB）**があるため、PDFはバイナリ直返しせず
  **Supabase Storage に保存してダウンロードURLを返す**（`doyaslide/export` で確立済みのパターン）
- 出力形態: ダウンロード / メール送付（`src/lib/email.ts:sendEmail()`）/ 期限付き共有リンク
- A4縦・1〜複数ページ・明細が多い場合の改ページとヘッダ繰り返しに対応

### F6. 承認フロー（重要）

**AIが出した金額をそのまま客先に出させない。**

- 見積書は `draft → 確定 → 送付済` のステータスを持つ
- `draft` のPDFには **「社内確認用」の透かし**を入れる
- 確定操作は人間が明示的に行い、確定者と日時を記録する
- 組織設定で「一定金額以上は admin+ の承認が必要」を有効化できる（Phase 2）

### F7. 連携

| 連携先 | 内容 | 時期 |
|---|---|---|
| **ドヤAI商談（`aishodan`）** | 商談中に見積もりを生成。ヒアリング済みスロット（人数・予算・時期）を初期値として渡す。その場でPDF提示・送付 | Phase 3 |
| **ドヤ営業管理（`sfa`）** | 見積書を商談（Deal）に紐づけ、金額を商談金額へ反映。ステージ「見積」へ自動遷移 | Phase 2 |
| ドヤ商談準備（`shodan`） | 相手企業の規模・業種を初期値に反映 | Phase 2 |
| Slack | 見積書の確定・送付を通知（`src/lib/notifications.ts`） | Phase 1 |

> ドヤ営業管理の既定パイプラインには既に**「見積」ステージ**が存在する。ここに実物の見積書が紐づくと、
> 「提案 → 見積 → 交渉」の流れがシステム上で完結する。

## 4. データモデル（Prisma / `quote_*`）

組織スコープ型の共通パターン（`sfa` / `shodan` / `aio` と同型）に従う。

```
quote_organization    組織（slug, name）
quote_member          メンバー（userId, role: owner>admin>manager>member）
quote_invitation      招待（unique token）

quote_issuer          発行者情報（社名/住所/電話/ロゴ/角印/インボイス番号/銀行口座）
quote_product         商材（name, sourceUrl, profile Json）
quote_rate_card       自社単価マスタ（productId, itemName, spec, unit, unitPrice, taxRate, isDefault）
quote_market_price    相場マスタ（category, itemName, min, median, max, unit,
                                  sourceType: own_media|competitor|manual, sourceUrl, collectedAt）
quote_template        見積テンプレート（name, lines Json）

quote_document        見積書（orgId, productId, quoteNo unique, title,
                              clientCompany, clientDept, clientPerson,
                              issueDate, expiryDate, paymentTerms, deliveryTerms, notes,
                              discountType, discountValue, status: draft|confirmed|sent,
                              confirmedBy, confirmedAt, sentAt, totalExclTax, taxAmount, totalInclTax)
quote_line_item       明細（documentId, ord, itemName, spec, qty, unit, unitPrice,
                            taxRate, amount, priceSource, sourceRef)
quote_export          出力履歴（documentId, format, storagePath, downloadUrl, expiresAt, createdBy）
```

- 全ての `[id]` 系APIは `findFirst({ where: { id, organizationId } })` の**二重条件**必須（IDOR防止）
- 金額は**整数（円）**で保持し、浮動小数を使わない（丸め誤差の実害を避ける）
- ⚠️ モデル追加後は `npx prisma generate` ＋ **本番は手動 db push**（Vercelビルドは設計上スキップ）

## 8. コンプライアンス・リスク

1. **金額はAIの参考値であり、確定は人間が行う** — 承認フロー（F6）で担保。`draft` は透かし必須
2. **相場情報の扱い** — 出典を必ず表示。競合価格は**公開情報のみ**を収集し、断定的な比較表現をしない
3. **消費税・インボイス** — 税率区分と丸め規則の誤りは実害。固定ルール＋検算テストを必ず用意する
4. **見積書の法的性質** — 見積書は契約ではなく「申込みの誘引」。有効期限と「本見積書は契約を構成しない」旨を記載
5. **顧客情報** — 宛先の会社名・担当者名は個人情報。組織スコープで分離し、保存期間を定める
6. **相場の陳腐化** — `collectedAt` を持ち、古い相場には「〇ヶ月前の情報」と明示する

## 10. 主要リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **相場が根拠なしのハルシネーション** | 誤った価格で失注・信用毀損 | 出所4層の優先順位を固定。該当なしは「要見積」で空欄。LLM単独禁止 |
| 消費税・丸めの計算ミス | 金額不一致・実害 | 整数（円）保持、丸め規則を1箇所に集約、検算スクリプトを `scripts/` に用意 |
| PDFの日本語文字化け | 使い物にならない | puppeteer方式を採用（adsimで実績あり）。jsPDF単体は使わない |
| PDFがVercelのレスポンス上限超過 | 出力失敗 | Supabase保存＋URL返却（doyaslideで確立済み） |
| AI出力をそのまま客先送付 | 誤った金額の対外流出 | `draft` 透かし＋人間の確定操作を必須化 |
| 競合価格の収集が不安定 | 相場が埋まらない | 自社メディアの相場表を初期シードにして、収集は補強に留める |

### 設計判断（実装時に確定）

- **金額の出所は4層**（自社の公開価格 → 相場マスタ → 競合 → 要見積）。画面に1件ずつ表示する。
- **`market` を名乗る金額は相場マスタと突き合わせる。** 該当が無ければ根拠なし（`unknown`）へ落とす。
  プロンプトで「根拠が無ければ空欄」と指示しても、モデルは必ず「それらしい数字を埋める」側へ倒れるため、
  生成後の機械チェックが要る（mensetsu の分岐分類器と同じ挙動）。
- **「要見積」の行は合計に含めない。** 0円として足すと総額を誤らせる。PDFにも「要見積」と印字する。
- **消費税は税率ごとに区分計算し、値引きは税率別小計へ按分する。** 行ごとに丸めると合計が合わない。
- **下書きPDFには「社内確認用」の透かしを入れる。** AIが出した金額を、人が確認する前に客先へ渡させないため。
- 相場マスタ（`market.ts`）の出典は**ドヤマーケAIメディアで公開している自社調査データ**。
  更新するときは出典記事も併せて直すこと。

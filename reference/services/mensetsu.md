## 1. ユースケース

### 1-1. 採用担当者（企業側）
1. 組織を作り、自社URLを入力する
2. AIが企業情報を読み取り、**その会社に合った質問セット＋評価基準（ルーブリック）**を自動生成する
3. 担当者が質問・基準を微調整して「面接テンプレート」として保存する
4. 応募者に面接URL（ワンタイム）を発行して送る
5. 面接完了後、評価レポート・全文ログ・録画を確認し、**人間が最終判断**する

### 1-2. 応募者
1. 送られたURLを開く → 同意画面（録音・AI利用・個人情報）
2. カメラ/マイク確認 → 接続テスト
3. Zoom風の画面でAI面接官と会話（15〜30分）
4. 終了 → 「結果は追ってご連絡します」（応募者に即時スコアは出さない）

## 2. 機能要件

### F1. リアルタイムAI面接（コア）
- **F1-1** Zoom風レイアウト。左（大）にAIアバター、右下に応募者の自映像、下部に操作バー（ミュート/カメラ/字幕/退出）、上部に残り時間と進行度
- **F1-2** AIアバターが音声で質問する。日本語。話速・間・相槌を自然に
- **F1-3** 応募者は口頭で回答。**発話中はAIが黙る**（バージイン対応：応募者が話し始めたらAIの発話を即停止）
- **F1-4** 回答内容を踏まえた**動的な深掘り**（1問につき最大2回まで追加質問）
- **F1-5** 沈黙が一定秒続いたら助け舟（「言い換えると…」）／それでも無反応なら次の質問へ
- **F1-6** 字幕（自分・面接官の双方）をリアルタイム表示。オンオフ可
- **F1-7** 想定所要時間を超えたら未消化質問をスキップして締めに入る
- **F1-8** 通信断からの復帰（再接続して同じセッションを継続。3分以上でセッション終了・部分評価）

### F2. 評価・フィードバック出力
- **F2-1** 評価軸（コンピテンシー）ごとに **1〜5点＋根拠となる応募者の発言の引用** を出す
- **F2-2** 総合判定を **`推奨` / `条件付き推奨` / `保留` / `見送り`** の4段階で出す（※二値の「合否」ではなく推薦度。最終決定は人間）
- **F2-3** 応募者向けフィードバック（強み・改善提案）と、採用担当者向けレポート（懸念点・次面接で聞くべきこと）を**別文面**で生成
- **F2-4** 評価不能な軸は「情報不足」と明示する（推測で埋めない）
- **F2-5** レポートPDF出力（ドヤ商談準備の帳票実装を流用）

### F3. 企業URLから質問セット自動生成（追加機能a）
- **F3-1** URL入力 → スクレイプ（`src/lib/adbanner/scrape.ts` / `src/lib/shodan/research.ts` を流用）
- **F3-2** 事業内容・提供価値・カルチャー・採用ページの求める人物像を抽出
- **F3-3** 法人情報の補完に gBizINFO（`GBIZINFO_API_TOKEN`、`limit≤5000` / `page≤10` の実測上限あり）
- **F3-4** 職種・レベル（新卒/中途/マネージャー）を選ぶと、**質問10〜15問＋評価軸5〜7個＋各軸のルーブリック**を生成
- **F3-5** 生成物は編集可能。**構造化面接**方式（全応募者に同じ主質問・同じ基準）を既定とする

### F4. ログ蓄積・ナレッジ化（追加機能b）
- **F4-1** 全発話の逐語ログ（話者・タイムスタンプ・音声区間）を保存
- **F4-2** 質問単位で「回答要約 / スコア / 判断理由」を保存
- **F4-3** **模範回答ライブラリ**：担当者が過去の回答に「これはOK/NG」とラベル付け → 次回以降の採点の参照例（few-shot）に使う。これが蓄積されるほど自社基準に寄る
- **F4-4** 候補者間の横並び比較ビュー（同一質問での回答・スコアを並べる）
- **F4-5** 録画（音声必須／映像は任意）を Vercel Blob に保存、保持期間を組織設定で指定

### F5. 管理・運用
- **F5-1** 組織・メンバー招待（`MensetsuOrganization` / `MensetsuMember` / 招待トークン）
- **F5-2** ワンタイム面接リンク（有効期限・1回限り・受験者メール紐付け）
- **F5-3** 面接一覧（ステータス：未実施 / 実施中 / 評価済 / 期限切れ）
- **F5-4** 組織設定：録画保持日数、映像収録の要否、応募者へのフィードバック開示可否

## 3. 技術構成

### 3-1. リアルタイム会話エンジン

**採用: OpenAI Realtime API（speech-to-speech / WebRTC）**

```
ブラウザ ──WebRTC──▶ OpenAI Realtime API
   ▲                        │
   │ ephemeral token        │ 音声＋transcript（イベント）
   │                        ▼
Next.js API Route ◀──── サーバ側で会話ログを受信・保存
(/api/mensetsu/session)
```

- サーバは**短命トークンを発行するだけ**。音声ストリームはブラウザ↔OpenAI直結
- → **Vercel Serverless で WebSocket を保持できない制約を回避できる**（`src/lib/cunning/transcribe.ts` 冒頭に記載の、カンニングが Phase 2 で想定していたのと同じ方式）
- speech-to-speech なので「文字起こし→LLM→TTS」の3段パイプより遅延が小さく、相槌・割り込み・間が自然になる
- 面接の進行制御（次の質問へ / 深掘りするか / 締めるか）は **Realtime の function calling** で行い、サーバがステートを持つ

**却下した案**
- 文字起こし(gpt-4o-transcribe) → LLM → TTS の自前3段：遅延が積み上がり「会話」にならない。カンニングは片側音声の要約なので成立するが、双方向面接では不可
- AssemblyAI streaming：`ASSEMBLYAI_API_KEY` はあるが、STTのみで応答生成・音声合成は別途必要

### 3-2. アバター描画（**要判断ポイント**）

音声はRealtime APIが出す。**その音声に口と表情を合わせる層**をどうするかは分離設計にする（`AvatarRenderer` インターフェースで差し替え可能に）。

| 案 | 見た目 | 月額コスト | 実装量 | 備考 |
|----|--------|-----------|--------|------|
| **A. 自前2.5Dアバター** | イラスト調。口形状差し替え＋瞬き＋うなずき | **0円** | 中 | 音量エンベロープでリップシンク。ドヤブランドの自作キャラ路線と整合 |
| **B. HeyGen Interactive Avatar** | ほぼ実写 | $99〜＋従量 | 小 | 要件(a)「実際の人間のように動く」に最も近い。ただしHeyGen側もLLM/音声を持つため二重構成になりやすい |
| **C. Simli / D-ID** | 実写寄り | Bより安 | 中 | 音声ストリームを渡すと顔動画が返る。日本語の口形状精度は要検証 |

**推奨：Phase 1 は A で作り切り、`AvatarRenderer` の差し替えで B/C を後から評価する。**
理由は、(1) 外部依存を Realtime API 1本に抑えられる、(2) 月額固定費ゼロで検証できる、(3) 面接体験の本質は会話の自然さ（遅延・深掘り精度）であり、そこは A/B/C で変わらないため。
※「実写級でなければ要件を満たさない」判断であれば Phase 1 から B にする。**ここは要ご判断。**

### 3-3. 質問生成・評価

| 用途 | モデル | 理由 |
|------|--------|------|
| 面接中の対話・進行 | OpenAI Realtime（`gpt-realtime` 系） | 低遅延の音声対話 |
| 企業URL→質問セット生成 | Claude（`ANTHROPIC_API_KEY`）or Gemini | 長文の企業情報読解。バッチ処理なので遅延不問 |
| 面接後の評価・レポート | Claude | 逐語ログ全文＋ルーブリック＋模範回答例を読ませる長文推論 |

評価は**面接中ではなく面接後にバッチで実行**する。理由：面接中の低遅延モデルに採点までさせると会話品質が落ちるうえ、全体を見てからでないと相対評価ができない。

### 3-4. 画像・帳票
- レポートPDF：ドヤ商談準備の実装を流用
- 画像生成が必要な場合は必ず `src/lib/image-generator.ts:generateImageWithFallback()` 経由（直接API禁止）

## 7. コンプライアンス要件（必須・実装対象）

AI面接は法規制の対象になりうるため、以下は「あとで」ではなく Phase 1 の実装範囲に含める。

- **C1** 面接前に、①録音・録画されること ②AIが評価に関与すること ③データ保持期間 を明示し、明示的同意を取得（同意ログを保存）
- **C2** **AIの判定のみで不合格を確定させない。** 出力は「推薦度」であり、最終決定は人間が行う旨をUI・レポートの両方に明記
- **C3** 差別的評価の排除：性別・年齢・出身・家族構成・信条などを**質問生成時にブロック**し、面接中に応募者が自発的に述べた場合も**評価根拠に使わない**
- **C4** 応募者からの開示・削除請求に応じる導線（個人情報保護法）
- **C5** 録画・逐語ログの保持期間を組織設定で管理し、期限切れを自動削除するcron
- **C6** EU/英国在住者を扱う場合は追加要件（EU AI Actで採用は高リスク分類）。Phase 1 は**日本国内向けに限定**し、その旨を規約に明記

## 8. 非機能要件

| 項目 | 目標 |
|------|------|
| 応答遅延 | 応募者の発話終了 → AI発話開始まで **1.5秒以内**（Realtime APIで実測 ~0.5〜1.0秒） |
| バージイン | 応募者の発話検知から **300ms以内**にAI発話停止 |
| 同時面接数 | Phase 1 は組織あたり同時5セッション |
| 面接時間 | 既定20分（10/20/30分から選択） |
| 対応ブラウザ | Chrome / Edge / Safari 最新版（WebRTC・getUserMedia必須）。モバイルはPhase 2 |
| 音声品質 | ノイズ抑制・エコーキャンセル（ブラウザ標準制約を有効化） |
| コスト | Realtime API の従量課金が主。1面接20分あたりの想定単価を計測し、統一プランの原価管理に反映 |

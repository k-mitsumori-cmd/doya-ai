# 要件ドキュメント: ドヤAI質問リンク

## 1. 概要

自社サイトのURLを1つ入力すると、そのサイトに置く「AI質問ボタン」一式を作るツール。

| 出力 | 数 | 内容 |
| --- | --- | --- |
| AI質問リンク | 2本 | ChatGPTを開き、サイトに合わせた質問文が自動で送られるURL |
| ポップアップ用バナー画像 | 3種類 | 「AIに聞く」ボタン付きのバナー。リンク先に上のURLを設定して使う |

どれもワンクリックでクリップボードにコピーできる。利用者はコピーしたURLと画像を、HubSpot などのポップアップツールに貼るだけで設置が終わる。

- サービス名: ドヤAI質問リンク（ドヤシリーズ。全体名はドヤAI、旧称ドヤマーケAIは使わない）
- serviceId（案）: `asklink`、パス `/asklink`
- 想定利用者: 自社サイトを運用するマーケ担当者（BtoB・BtoC両方）
- 価値: 開発ゼロ・チャットボット導入ゼロで、訪問者がサイトについてAIに相談できる入口を置ける

## 2. 仕組み（前提知識）

- ChatGPTは `https://chatgpt.com/?q=<URLエンコードした質問文>&hints=search` を開くと、質問文を入力欄に入れて送信する。`hints=search` を付けるとウェブ検索をしてから答える。
- `q` と `hints` は OpenAI の公式仕様ではない。将来動かなくなる可能性があるため、画面と利用規約相当の注意書きにそう書く。
- **質問文は、ボタンを押した訪問者本人の発言として ChatGPT の画面に表示される。** ここが品質のすべて。指示書のような文面だと、訪問者が自分で命令したように見えて不快になる（実際にユーザーから指摘があり、作り直した経緯がある）。

## 3. 利用の流れ

1. URLを入力して「作成する」を押す
2. サイトを読み取り、会社・サービス・強み・対象顧客・主要ページを抽出する。ToB/ToCを判定して表示する（利用者が切り替え可能）
3. 質問リンク2本を作る（数秒〜十数秒）
4. バナー画像3種類を作る（時間がかかるので、リンクを先に表示し、画像は順に出す）
5. 結果画面でそれぞれをコピー、またはChatGPTで試す
6. 履歴から過去の結果を開き直せる

## 4. 機能要件

### 4-1. サイトの読み取り

- 既存の読み取り処理を再利用する（候補: `src/lib/adimage/brand.ts` の `analyzeBrand()`、`src/lib/shodan/research.ts`）。新規にスクレイパーを書かない。
- 抽出項目: 会社名またはサービス名、サービス内容、強み、対象顧客、ToB/ToC、問い合わせ・無料相談のURL、資料ダウンロードのURL、料金ページのURL、その他の主要ページのURL、ブランドの主要色。
- **URLはサイト上で実際に見つかったものだけを使う。** 生成側が作ったURLは機械チェックで弾く（4-2）。見つからない項目は「未確認」として画面に出す。
- 読み取れないサイト（ブロック、SPAで本文なし等）は、サービス説明を手入力して続行できるようにする。

### 4-2. AI質問リンク（2本）

**どの2本を作るか（ToB/ToCで切り替え）**

| 判定 | 1本目 | 2本目 |
| --- | --- | --- |
| ToB | 「◯◯で何ができる？」サービス理解から、自社に合う使い方と相談文まで | 「無料相談・問い合わせの準備をしたい」聞いておく質問・用意するもの・フォームに貼る相談文 |
| ToC | 「自分に合う商品・プランを選びたい」好みや状況を聞いて候補を絞る | 「購入・予約の前に不安を解消したい」よくある不安の確認と、次に見るページ |

ボタン名（15字以内）も一緒に作る。問い合わせ窓口が見つからないサイトでは、2本目を「資料・ページ選び」に差し替える。

**質問文の書き方ルール（プロンプトに入れ、さらに生成後に機械チェックする）**

- 訪問者の一人称（私・うちの会社）で、丁寧で前向きな話し言葉。書き出しは「〜が気になっています」「〜したいと思っています」など訪問者の気持ちから始める
- お願いは「〜してもらえますか」「〜だと助かります」の形
- 最初に「〜の3つを、答えやすい選択肢つきで1問ずつ聞いてもらえますか？」と、何を聞いてほしいかを書く（ToBの例: 業種・会社の規模・相談したいこと。ToCの例: 用途・予算・重視する点）
- サイトの要点は「〜があるようですが」のように、訪問者が知った情報として入れる
- 最後に「私に合いそうなページも教えてください」の趣旨で、4-1で確認できたURLを1〜2個入れる
- 料金や実績などサイトで確認できないことは「相談で確認したいことに入れておいてください」と書く
- 1本450字以内

**機械チェック（不合格なら最大2回まで再生成、それでも不合格なら「要確認」表示）**

- 禁止表現を含まない: 「あなたは」で始まる役割指定、「〜しないで」「〜するな」「禁止」、「誘導」「案内役」「次の一手」「CV」、`utm_`
- 文中のURLがすべて4-1の抽出URL集合に含まれる
- 450字以内
- エンコード後のURL全体が4,000文字以内

> 「プロンプトで禁止すれば守られる」と仮定しない。ドヤ見積もりAIで、プロンプトで止めた数字をモデルが埋めた実績がある（`reference/services/quote.md`）。チェックはコードで行う。

**URLの組み立て**

- サーバー側で `'https://chatgpt.com/?q=' + encodeURIComponent(質問文) + '&hints=search'`。手書きのエンコードや文字列置換はしない。
- 日本語はエンコードで約9倍に伸びる。判定は文字数ではなくURL長で行う。

**模範（ドヤマーケ向けに作って確認済みの書き方）**

> ドヤマーケの無料相談（https://doyamarke.surisuta.jp/download/base02_doyamarke-free-1）を申し込もうと思っています。せっかくの30分なので、しっかり準備して臨みたいです。
> まず私の業種・会社の規模・相談したいことの3つを、答えやすい選択肢つきで1問ずつ聞いてもらえますか？そのうえで、次の3つを作ってもらえると助かります。
> 1. 相談で聞いておくとよい質問5つ（費用・期間・成果の目安・自社で担当する範囲も含めて）
> 2. 事前に用意しておくとよい数字や資料のチェックリスト
> 3. 申し込みフォームに貼れる200字くらいの相談文
> 料金や実績など、サイトで確認できないことは「相談で確認」としておいてください。

この文面をプロンプトに例文として丸ごと入れない。例文はそのまま出力に写り、どのサイトでも同じ文になる。ルールと型で伝える。

### 4-3. ポップアップ用バナー画像（3種類）

**参考デザイン（ユーザー提供のドヤマーケ版）**: 淡い青のグラデーション背景。左上にサービス名、左に大見出し「その疑問、AIに聞いてみよう。」、その下に小見出し「ドヤマーケの使い方を、会話でチェック。」、右に吹き出し3つ（「何を頼める？」「どう活用する？」「何を解決できる？」）、下中央に濃紺の丸ボタン「AIに聞く →」、その下に小さく「ChatGPTが開きます」。

**3種類の定義（案。未決事項で確定）**

| 種類 | サイズ | 用途 |
| --- | --- | --- |
| 横長 | 1200×672 | PCの中央ポップアップ |
| 正方形 | 1088×1088 | スライドイン・SNS兼用 |
| 縦長 | 1152×1536 | スマホのポップアップ |

サイズは16の倍数・アスペクト比3:1以内にする（gpt-image-2の受理条件。`reference/services/adimage.md`）。

**作り方**

- 既存の `src/lib/image-generator.ts` の `generateImageWithFallback()` 経由で生成する。画像APIを直接呼ばない。
- 文字は画像生成AIに一枚絵として描かせる。後から文字を重ねる合成はしない（ユーザーの明示方針。adimage と同じ）。
- 焼き込んだ文字は `src/lib/adimage/verify.ts` の検査（OCR照合・混入検出）を流用して確認し、不合格なら最大2回まで再生成する。検査自体が失敗したら合格扱いにせず「要確認」を出す。
- 書き出しは縮小のみ。切り抜き（`fit: 'cover'`）で文字を壊さない。
- 文言はサイトごとに生成する: 見出し（12字前後）、小見出し（20字前後）、吹き出し3つ（各8字以内、1本目のリンクの質問内容に合わせる）、ボタン「AIに聞く」、注記「ChatGPTが開きます」。
- 色はサイトの主要色に寄せる。読み取れなければ参考デザインの青系。
- ロゴ合成は Phase 2（`src/lib/adimage/logo.ts` を流用予定）。
- モデルと品質は adimage と同じ設定（gpt-image-2・medium）を基準にし、変える場合は承認を取る。

### 4-4. 結果画面とコピー

| 要素 | ボタン |
| --- | --- |
| 質問リンク（2本） | 「URLをコピー」「質問文をコピー」「ChatGPTで試す」（新しいタブ） |
| バナー（3種類） | 「画像をコピー」（PNGをクリップボードへ）「ダウンロード」 |
| 設置用HTML | 「コードをコピー」: バナー画像＋リンク（`target="_blank" rel="noopener"`）のimgタグ一式 |

- コピーは `navigator.clipboard.writeText` / `ClipboardItem`（image/png）。失敗時はテキスト選択、画像はダウンロードに落とす。成功時はボタンの表示を「コピーしました」に変える。
- 各リンクにボタン名・質問文・文字数・URL長・チェック結果（合格／要確認）を表示する。
- 質問文は画面上で編集でき、編集すると URL を作り直して機械チェックをやり直す。
- 「使い方」欄に、HubSpot等のポップアップでボタンのリンク先にURLを貼る手順と、ChatGPT経由の再訪はGA4の参照元 `chatgpt.com` で見られることを短く書く。

### 4-5. 履歴

- 入力URL・判定・抽出結果・リンク2本・バナー3枚を保存し、一覧と詳細で開き直せる。
- 他人の結果は見られない（userId / guestId でスコープ。IDOR防御）。

## 5. 非機能要件・ドヤAI規約

- 既存の作りに合わせる: ページ `src/app/asklink/`、API `src/app/api/asklink/`、ロジック `src/lib/asklink/`、LPは `src/components/lp/` の共通キット（page.tsx + layout.tsx + lp-data.ts）。
- 料金は統一プラン（無料 / プロ ¥9,980）。プラン判定は `User.plan` のみ。`services.ts` に pricing を定義し、`UnifiedPricingPlans` を設置、`src/lib/stripe.ts` の `ALL_SERVICE_IDS` に追加。個別 checkout は作らない。
- 無料枠は `src/lib/plan-limit.ts` に集約し、`services.ts` の宣言とコードを一致させる。判定は LLM・クロール・画像生成の**前**に行う。
- 公開は開発中扱いから: `UNLISTED_SERVICE_IDS` に入れ、`status: 'coming_soon'`、`badge: 'BETA'`、LPに `noindex`。
- ドヤシリーズの見た目に揃える: UIは日本語、絵文字は使わない（UIアイコンは Material Symbols、サービス固有の画像は5-1でCodexに依頼）、ブランドカラー `#0066ff`。サービス一覧・ツール切替・料金ページに他のドヤシリーズと同じ形で並ぶ。
- 画像は Supabase Storage に保存し、署名URLで返す。
- 長い処理はリンクと画像で分け、画像は1枚ずつ進捗表示。1枚のタイムアウトと同時実行数は adimage に合わせる。

## 5-1. システム画像はCodexに依頼する

システム側で使う画像は、Codexの内蔵画像生成（定額枠）で作る。Claude Code からは従量課金の画像APIを呼ばない。

| 画像 | サイズ（目安） | 置き場所（案） |
| --- | --- | --- |
| サービスアイコン | 512×512 | `public/asklink/icon.png` |
| LPのメイン画像（ボタンを押すとChatGPTが開く様子） | 1600×900 | `public/asklink/lp-hero.png` |
| LPの手順3枚（URLを貼る→リンクとバナーができる→ポップアップに貼る） | 各1200×800 | `public/asklink/lp-step1〜3.png` |
| 結果画面・LPのサンプルバナー3種（4-3の3サイズ） | 4-3の表どおり | `public/asklink/sample-*.png` |
| 空状態のイラスト（履歴が0件） | 800×600 | `public/asklink/empty.png` |
| OG画像 | 1200×630 | 既存の `/og/[...slug]` で足りるならそれを使う |

進め方:
1. Claude Code が画像ごとの依頼文を作り、`reference/services/asklink-images.md` にまとめてユーザーに渡す
2. ユーザーがCodexで生成し、上の置き場所に置く（またはCodexに直接置いてもらう）
3. Claude Code が組み込み、表示を確認する。画像が揃うまでは仮の枠で実装を進める

依頼文の型（1枚ごと）:
```
ドヤシリーズ「ドヤAI質問リンク」の<用途>の画像を作ってください。
サイズ: <幅>×<高さ>px / 形式: PNG
内容: <何を描くか>
文字: <画像内に入れる日本語。無ければ「文字なし」>
トーン: ドヤシリーズの青（#0066ff）を基調に、白と淡い青。濃紺 #0a0f3c をアクセント。清潔でフラット、写真ではなくイラスト調
入れないもの: 絵文字、他社のロゴ・商標（ChatGPTのロゴも描かない。「ChatGPT」は文字だけ）、実在の人物
保存先: <置き場所>
```

## 決定事項（2026-10-08。6章の未決事項への回答）

1. **利用枠**: ログイン必須（ゲストは使えない）。無料 累計3回 / プロ 月30回 / エンタープライズ 月100回。1回＝リンク2本＋バナー3枚。
   - ゲストを止めた理由: Cookie 単位の上限は Cookie を消せば回避でき、1回ごとに画像3枚の費用が出る（adimage が 2026-08-17 に同じ理由でログイン必須化）。
   - 正本は `src/lib/plan-limit.ts` の `asklinkRuns`。`services.ts` の表示文言と一致させる。
   - 判定は run の作成時（クロール・LLM・画像生成の前）。Serializable トランザクションで数えて作る。読み取れなかったサイト・作成失敗の run は削除して枠を戻す。
2. **バナー3種類**: 4-3 の3サイズ（横長 1200×672 / 正方形 1088×1088 / 縦長 1152×1536）。設置場所が違うので、同サイズのデザイン違いより実用的。
3. **リンクの本数**: 無料・プロとも2本。増やすのは Phase 2。
4. **Claude・Perplexity 用リンク**: 出さない。バナーの注記が「ChatGPTが開きます」で、非公式パラメータへの依存先も増えるため。
5. **原価**: gpt-image-2 medium を1枚$0.05〜0.07と見込むと、1回（3枚）で通常約$0.2、作り直しが最大まで出て約$0.6。プロ30回で月¥900〜2,700程度。初回の実生成（承認後）で実額を確認して更新する。
   - バナーは1種類につき生成2回まで（初回＋作り直し1回）。1回の生成は検査不合格で最大3試行（初回＋再生成2回）。150秒を過ぎたら次の試行を始めない（maxDuration=300）。
   - ToB/ToC の切り替え等によるリンクの作り直しは1回の作成につき10回まで（LLMのみ）。

### 実機確認（2026-10-09）

- ドヤマーケで作ったリンク（質問文393字・URL 2,935文字）を Chrome のログイン済み ChatGPT で開き、**質問文が末尾のURLまで欠けずに入力欄へ入る**ことを確認した。`hints=search` で「ウェブ検索」も有効になる。
- ⚠️ 2章の想定と違い、**自動送信はされず入力欄に入った状態で止まる**（訪問者が送信を押す）。LPのFAQはこの挙動に合わせて書いた。
- 抽出: 無料相談ページ（`/download/base02_doyamarke-free-1`）を正しく取得。料金ページの無いサイトでモデルがトップページを「料金」に選んだため、トップは専用ページとして採らない（未確認に落とす）ようにした。
- 質問文: 4本中3本が初回で合格。URLが入らない文が出たため、URLが1つも無いものは作り直す。ボタン名が15字を超えたものは既定のボタン名に差し替える。番号つきの項目は改行して書かせる。
- バナー: gpt-image-2 medium で3サイズ（計7回生成）。正方形・縦長は合格。横長は画像は正しいが OCR（gpt-4o）が「ChatGPTが開きます」を「聞きます」と読み違えて要確認になった（誤判定）。
  - 原因: 同じ画像内の「AIに聞く」に引きずられる。全体のままでも、上下半分に切っても読み違えた。注記だけの細い帯にすると正しく読めた。
  - 対策: 1回目で足りない文言があれば、縦を8本の細い帯（高さ16%・少しずつ重ねる）に切って2倍に拡大して読み直し、どちらかで読めれば合格とする（読み取り8回で約$0.02。画像の作り直し約$0.05より安い）。
  - 再判定の結果、3枚とも合格。
- 修正後の再生成（2026-10-09）: ToB 2本・ToC 2本の4本すべて合格し、すべてに文中URLが入った（料金ページは「未確認」に正しく落ちた）。

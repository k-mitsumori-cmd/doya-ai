# ドヤペルソナAI

## 概要
- **パス**: `/persona`
- **サービスID**: `persona`
- **説明**: WebサイトURLからターゲットペルソナ + クリエイティブを自動生成
- **ステータス**: active
- **カテゴリ**: text + image

## 機能
- URL入力 → HTML取得・解析 → Gemini でペルソナ生成
- ペルソナ: 日本式履歴書フォーマット (基本情報, 職歴, スキル, 行動パターン, 課題)
- ポートレート画像生成 (Gemini 3 Pro Image Preview)
- バナー画像生成 (6サイズプリセット + キャッチコピー選択)
- シーン画像生成 (日常シーンの可視化)
- LP構成案・広告コピー (Google/Meta)
- メールドラフト
- マーケティングチェックリスト (優先度付き)
- 生成履歴 (localStorage, 最大20件)

## APIエンドポイント (4)

| メソッド | パス | 説明 | AIモデル |
|---------|------|------|---------|
| POST | `/api/persona/generate` | ペルソナ + クリエイティブ + チェックリスト | gemini-2.5-flash → gemini-flash-latest (fallback) |
| POST | `/api/persona/portrait` | ポートレート画像生成 | gemini-3-pro-image-preview |
| POST | `/api/persona/banner` | バナー画像生成 | gemini-3-pro-image-preview |
| POST | `/api/persona/scene` | シーン画像生成 + スケジュール・日記 | gemini-3-pro-image-preview |

## ペルソナ生成の流れ

```
1. ユーザーがURL入力
2. サーバーがHTML取得 (fetch)
3. HTML解析 (title, meta, headings, bodyテキスト抽出)
4. Gemini API でペルソナJSON生成:
   - 基本属性 (年齢, 性別, 職業, 年収, 居住地)
   - 行動パターン (情報収集, 購買行動)
   - 課題・ニーズ
   - クリエイティブ提案 (LP構成案, 広告コピー, メール)
   - チェックリスト
5. (自動) ポートレート画像を別APIで生成
6. (オプション) バナー画像生成
```

## 履歴のアカウント分離（2026-09-20 ローカル補修）

- 認証確定後だけ、`persona:v2:<encoded userId>:doya_persona_last/history` を使用する。
- 生成画面・履歴画面はアカウント切替で内部状態を破棄する。退出後に届いたテキスト/画像の結果は画面・保存先へ反映しない。
- 旧共有キーは所有者を確認できないため自動移行・表示しない。既存の保存値は削除しない。
- 履歴はブラウザ内最大20件。別端末には同期しない。保存失敗は明示し、生成結果は画面に保持する。削除失敗時は一覧を消さず、読み込み用保存の失敗時は遷移しない。
- localStorage はサーバーのアクセス制御や暗号化保存の代わりではない。画像の履歴反映、再表示時の自動画像生成、同一アカウント複数タブの同時履歴更新は別途検証対象。

## 履歴閲覧と画像生成（第258巡・ローカル）

履歴復元では画像生成APIを自動実行しない。現在の画面で新規生成/文章変更が成功した場合に限り画像を自動生成する。履歴の不足画像は利用者が「不足している画像を生成する」を選び、画像の利用枠を使用する旨を確認できる。保存された画像は引き続き復元する。

## 履歴の画像と変更後データ（第259巡・ローカル）

新規生成と文章変更はUUID付きの履歴を保存する。変更前も最大20件の範囲で保持する。画像はIDと文章が一致する履歴にマージし、別のlastや削除済みの履歴を上書き・再作成しない。画像保存に失敗した場合も画像を画面に保持して保存失敗を表示する。IDなしデータに画像を推測で書き込まない。複数キーへの保存は原子的ではなく、容量不足は利用者へ案内する。

## 履歴削除・他タブ（第260巡・ローカル）

単件削除は最新配列から対象を除き、一致するlastも削除する。全削除はlast/history両方が対象。履歴選択は最新の保存レコードを読み、既に削除されていれば拒否する。同アカウントの他タブで削除した履歴は生成画面の表示と保留中の応答も無効にする。他タブの同時read/writeの排他は別途検証・補修対象。
